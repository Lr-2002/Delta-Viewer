# 1.4.4 骨架稳定性恢复与任务中心提醒诊断

日期：2026-10-29。对比版本：1.4.2、1.4.3、1.4.4。

## 骨架抖动

**确认 1.4.3 的默认骨架来源变更会造成回归。** 为减轻因果滤波的动作延迟，该版把 `raw_smpl_joints` 提升为首选；同一 NPZ 同时包含原始和处理结果时，之前正常播放的滤波骨架也会变成原始估计。原始估计保留了逐帧噪声，不能用“跟随同一相机帧”代替平稳性验收。

只读复核已留存的真实 `Fridge_051/smpl_skeleton.npz`：两个数组均为 544 帧、24 关节；用连续三帧坐标的二阶差范数评估高频变化，原始手腕的 P95 为 0.057026，滤波结果为 0.001875，约 30.4 倍。这个指标说明该样例的原始估计明显更抖，不表示所有数据都恰好相差同一倍数，也不能仅凭截图确定其具体数据条目。

1.4.4 恢复 1.4.2 的优先级：`joints`、`joint_positions`、`smpl_joints`、`skeleton`、`skeletons`、`keypoints3d`、`keypoints_3d`、`poses`；以上没有有效数组时才兼容原始估计。保持原处理结果，不再自动替换成高噪声原始结果。专属帧 ID 随所选数组读取，主相机采集时间映射、原生呈现追帧及整段固定地面保留。

这次没有添加滤波、改写源 NPZ 或固定提前若干帧。恢复滤波后，源算法自身的延迟仍可能存在，不能声称既恢复旧滤波结果又消除了它的全部时延。界面仍标注实际使用的滤波/原始估计。

## 任务中心红色提醒

**需要处理存储问题，提醒本身应保留。** 客户端成功读到服务器索引，并不代表索引仍在更新。“最近读取”是 Viewer 读文件的时间，“服务器最近统计完成”才是完整统计的时间；心跳超过 90 秒未更新才出现截图中的红色提示。

2026-10-29 09:53–09:54 对 `10.1.40.2` 只读检查：

- `/volume8` 总容量 63,331,842,916,352 字节，可用及空闲空间均为 **0 字节**，`df` 为 100%。源数据、统计输出和统计程序都位于此卷。
- `delta-viewer-task-index.service` 返回退出码 1，状态为 `activating / auto-restart`，每 15 秒自动重试。服务没有保持运行。
- 共享索引的完整统计停在 **2026-10-27 23:18:51（北京时间）**；状态文件最后心跳停在 **2026-10-29 00:00:52**，不是 Windows 客户端临时显示错误。
- 统计程序启动和运行时须原子写入状态、索引及核对确认文件。卷已满会阻止这些写入，因此反复点刷新不能解决。服务退出的具体 traceback 无可读取的 journal，系统日志需管理员权限，不能声称已读到某一条异常栈。

影响：批次名称和审核数量可能陈旧，展开后的进度及“仅未审核”筛选不能作为当前实时完成率；服务器批次核对和每晚完整统计无法正常确认。审核结论是否保存须看编辑器的本机/NAS 状态；该提醒本身不删除结论、不撤销领取，也不证明用户中心账号服务失效。NAS 满盘同时会阻止共享 QC 写入，本机持久待写结论需要保留，空间恢复后按原入口确认写回。

处理顺序：由存储管理员释放确认可清理的非原始数据或扩容，给写入留出持续余量；再确认统计服务恢复、心跳持续推进、完整统计成功以及批次核对有确认回执。只重启服务或隐藏红字均不能解决满盘。此次未删除数据、未迁移索引位置、未手工重启统计/工作台/用户中心/上传服务，未将旧进度标成实时。
