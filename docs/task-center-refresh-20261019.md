# 任务中心刷新问题调查与修复（1.1.6 / 1.1.7）

2026-10-19，审核员反馈点击任务中心刷新没有反应。调查确认既有交互反馈不足，也有服务器统计索引落后于源 QC 的实际问题。

## 事实与原因

- 旧按钮只重新读取服务器索引，没有成功或“暂无变化”提示；重读旧索引时页面看起来没有反应。
- 对反馈批次逐条只读核对 616 份根级 `session.json`，源 QC 已完成 616 条（497 通过、119 不通过）；索引仅完成 573 条（464 通过、109 不通过），43 条仍被显示为待审核。读取无失败。
- 服务心跳正常不能证明监听完整。检查该批次 618 个目录，发现末尾 9 个当前目录 inode 不在监听集合中。目录移走、同路径重新建目录后，旧实现只按路径字符串去重，仍监听旧 inode；该缺陷已隔离复现。
- 另有已被监听的目录也存在旧结果。因此不能断言全部 43 条都由同一种历史丢事件原因造成。按批次回读 QC 为漏事件提供明确的修复通道。
- 增量发布失败时，旧实现已修改内存节点，下一次重试可能认为无需发布；主循环也会清除待处理集合。本版同时修复内存回滚和失败后的保留重试。

## 最终行为

点击“刷新进度”立即显示刷新状态。展开的目录优先作为服务器 QC 核对范围，没有展开时选择本人领取的批次；选择批次子根时可核对该子根。范围去重、最多 32 个，不触发审核电脑全量扫描。没有明确批次时仅读索引，并提示展开批次后刷新。

客户端把只含索引相对范围的请求原子写入独立索引目录。服务器回读已知记录的根级 QC、更新聚合结果并补装监听，发布对应请求 ID、完成时间和 generation。客户端未收到确认时显示等待，失败显示原因，不将普通索引读取成功当作核对成功。完成后重新读取展开明细及未审核筛选；完整目录新增、删除仍由后台校准处理。

索引读取超过 20 秒提供可重试反馈，保留已有结果；同一路径复用未完成的底层读取，避免重试堆积线程。“最近读取”独立于服务器最近完整统计时间。账号、根目录切换后，旧异步结果不得覆盖新界面。

请求目录须有读写权限，服务器脚本需同步升级。拒绝路径穿越、数据集全根请求、符号链接及被移动的已知目录。只写服务专属索引和请求，不修改源 QC、媒体、领取归属或业务服务。

## 已取得的证据

- 服务器首次部署后，对应请求已收到成功确认，反馈批次恢复为 **616/616（100%）**；497 通过、119 不通过，0 异常。
- 缺少监听的末尾 9 个目录已全部恢复监听。
- 部署前后 616 份源 `session.json` 的组合 SHA-256 一致；仅统计索引发生变更。私有逐条核对及部署记录保存在本地 `artifacts/task-refresh-1.1.6/`，不提交原始数据。
- 服务器隔离回归 17 项通过，覆盖批次补漏、同路径目录替换、发布失败后无需新文件事件自动重试、穿越和中间符号链接拒绝、其他批次保持不变。
- 任务中心及索引读取回归 4 项通过，覆盖等待、双击去重、无变化反馈、请求失败不被无关成功覆盖、超时重试复用、未审核筛选和领取/释放。
- 已检查 1440×920、960×680、390×844，刷新文字和按钮无横向溢出。

三平台安装验证及目标 Windows 验证结果以本版 CI、Release 和部署记录为准；本报告中的浏览器隔离回归不能代替原生安装实测。

## 1.1.7 目标机发现与后续修复

1.1.6 三平台 Release 已完成并安装目标 Windows。原生实测发现另一层问题：NAS 已完成核对并更新心跳，Windows 仍反复读到固定 `status.json` 的旧内容，导致等待提示持续且错误地显示心跳过期。索引与状态还可能来自不同代，单独看到请求 ID 不足以保证读到对应计数。

1.1.7 改用每请求唯一的不可变回执，携带该次 manifest 和服务状态；原生读取验证请求 ID、格式、generation 及内容寻址分片，再选择对应统计或更新的固定索引。没有独立回执不能确认成功，回执写失败保留请求；回执及关联分片保留至少 24 小时。仅独立统计服务需要部署，不重启用户中心或工作台。

用户截图中的文字遮挡由 flex 布局压缩多行统计区引起：容器仍受最大高度和目录最小高度约束，提示文字超出被压缩高度进入目录区域。改为顶部内容不收缩、目录占用剩余高度并独立滚动；增加姓名/账号/未领取、批次名称、文件夹采集日期起止组合查询，不扫描源数据。

隔离回归已覆盖旧状态中有结果但无专属回执时继续等待、回执固定快照与后续新版本选择、回执发布失败保留请求、关联分片回收保护，以及 1440×920、960×680、390×844 的长列表滚动和多行错误提示不重叠。正式目标机最终验证与发布状态将在交付记录中列明。

服务器 1.1.7 回执流程已部署，仅重启独立统计服务。目标 Windows 的交互式桌面会话通过真实 UNC 共享读取唯一回执及对应分片并核验 SHA-256，结果为 616/616、497 通过、119 不通过、0 异常；NAS 源审核文件组合校验值仍与部署前一致。该项验证共享文件协议；完整应用按钮和滚动的安装后验证另见本次交付结果，不能与此协议检查混同。

本轮服务器隔离回归 18 项、任务中心及索引读取/查询回归 7 项、发布脚本 6 项、Wiki 15 页检查通过。原有 1.1.6 的隔离测试数字为该版本历史记录，不代表其目标机已消除 SMB 缓存问题。

发布前 `pnpm check:full` 通过，含前端构建、Clippy、191 项 Rust 库测试及 3 项 CLI 测试、Tauri debug 构建；14 项历史私有数据/环境测试按既有规则忽略。
