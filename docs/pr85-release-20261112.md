# PR #85 整合与发布（1.9.5）

按用户指示将 PR #85 合入当前1.9.4主线，使用未发布的1.9.5，保留 NAS 本地流畅播放、正常退出清理、播放定位与外发审核。应用标识仍为 `com.dohc.viewer`，原账号、队列、草稿和更新资产命名保持。

## 本次接入

- `config/d1-manager.json` v2 固定 PR 提供的 `http://deltadevice.cn:4174`、Factory 通道及日志接口；没有将历史无 scheme 占位当成正式协议依据。
- OTA 模块读取 `/ota/v1/channels/factory.json` 及清单引用资源，经设备 `/ota/upload/v1/session` 分块中继。设备 `GET /ota/status` 是处理结果来源。检查版本和下载中继均需用户操作；本次不执行真实设备升级。
- `trustRoot.publicKeyPem` 目前为空，软件不宣称验证发布签名，只验证大小与摘要；设备是独立验签方。配置公钥时启用已有 Ed25519 manifest 校验。设备回滚结果不能由“上传成功”推断。
- 诊断上传只处理用户选择的会话 `session.json`、`.session_meta/recording.log.jsonl` 和有界 `.gst.log`，最多200条结构化事件，使用真实 CID 关联设备，不上传图像和原始文件。当前没有新增任意地址或 shell 命令入口。
- 修正 OTA 旧结果在断连/读取失败后残留、更新时间始终缺失和 Type-C 仍显示读取中的问题；设备升级使用原生二次确认。日志读取移入 blocking worker，并参与 TaskControl。

## 验证与边界

本轮追加外发主工作区流转、AP／IP／Type-C 中文信息共用、片段定位后播放以及历史安装包内网下载。历史下载沿用固定镜像和原始安装器命名，单独保存到用户目录，不改变已选择的自动更新；回退为保存工作后手动运行旧安装包。未发布候选显示不可用，安装包保留 UNSIGNED 提示。镜像按需查询官方已发布 tag、核对三平台清单并流式转发，不一次缓存全部旧版；服务端与客户端均限制大小并计算摘要，客户端回读成功才 no-replace 发布。更新器 Ed25519/Minisign 链路没有改动；历史安装器的摘要验证不等同可信发布者验签。

用户已单独授权只更新并短暂重启下载镜像 10.1.41.17:17879，用户中心及审核服务不变。部署备份、hash、只读健康及历史包实测留在私有证据目录。当前 10.1.30.114 设备状态读取超时，已询问真实设备新地址，不能把夹具通过当三种方式全部实机通过。

本地 `pnpm check:full` 已通过，包含前端构建、Rust 测试、Clippy 和 Tauri debug 构建；镜像限流修正后的完整报告为 `artifacts/release-check/2026-11-12T05-05-22-559Z-linux-x64.json`。另外 `pnpm test:proofreading`、`pnpm test:d1-manager`（18 项）、`pnpm test:app-updates`（5 项）、`pnpm test:outbound-review`（2 项）、`pnpm test:update-mirror`（2 项）和 `pnpm check:wiki` 均通过。实际 App 回归覆盖任务中心到外发主工作区、历史下载，以及本地／云端两种面板在两种媒体时钟下的真实 MP4 片段起点；旧播放逻辑的负对照按预期失败。设备服务面板三视口回归覆盖状态失败清除、观测时间、Type-C 禁用、取消确认不提交及日志重试复用编号；夹具均不访问真实设备或外部端点。

下载镜像已在单独授权范围内更新，1.9.0 三平台完整安装包经内网流式下载，大小和 SHA-256 全部一致；用户中心启动时间和进程保持不变。上述本地门禁及内网下载结果不替代后续 GitHub CI、三平台正式资产验证或 Windows 正式产物实测。

合并采用单一 release-ready squash commit；main CI 后由既有 workflow 自动 annotated tag 和三平台完整 Release。正式资产、签名及 Windows 启动证据保存在工作树外，不以本地夹具通过冒充实机升级/生产上传通过。目标 Windows 只打开正式产物，保留其他窗口和用户数据；不重启业务服务，不推客户更新提醒。
