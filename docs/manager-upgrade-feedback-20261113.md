# 1.10.1 升级操作提醒与最新版本判断

升级页常驻说明改为黄色操作提醒：停止录制、自检和压力测试，保持连接和稳定供电，不关机或断电，以及设备默认电压／温度要求。隐藏常驻 SSH、Factory 下载、摘要和回滚实现说明；确认弹窗同步使用操作语言。技术边界仍见 [SSH 升级说明](manager-ssh-upgrade-and-outbound-20261113.md)，未改变原安装门禁或 Manager 自身更新验签。

用户点击“检查最新版本”后，管理端读取当前 Factory 发布资源，再通过固定 SSH `check` 动作核对设备实际 `VERSION` 和 `RELEASE.json`。版本号与发布批次均一致才记录 `UP_TO_DATE`，页面明确显示“当前已是最新版本，无需升级”，隐藏开始升级按钮。相同版本号而发布批次不同，继续提供升级入口，不按旧安装记录判断当前运行版本。

此检查不会在设备下载或接收安装包，不启动安装器。直接提交升级的 stage 和传包后的 launch 同样重新核对版本，避免重试或传输期间版本变化导致重复安装；已运行任务及 UNKNOWN 结果仍阻止另一次操作。检查记录保存在原有账号隔离日志中，可主动上传售后。

匹配结果调用设备已安装的 `system_monitor.audio_prompts.play_runtime_prompt` 及 `ota_up_to_date` 提示，沿用共享音频锁、功放控制和运行配置。每次明确检查产生一个操作编号；先保存结果，再尝试播报，同一编号重试及后台状态轮询不播报。语音禁用、资源缺失、播放超时或设备音频故障只记录警告，页面版本结果仍为无需升级，不误报安装失败。

验证覆盖：Python 隔离执行器的匹配／不匹配、不同发布批次、传输期间版本变化、活动操作、回执重试和语音失败；Rust 状态解析与最终日志；浏览器三种窗口宽度下的黄色提醒、最新结果、无重复安装、源发布批次变化及断连。完整发布检查、自动三平台构建和 Windows 正式包启动按本版交付结果记录。

提交前 `pnpm check:full` 已通过（报告 `2026-11-13T08-58-16-133Z-linux-x64.json`），包括 Rust 356 项、Python 执行器 15 项及 Tauri debug 构建；设备浏览器全套 19 项通过。补充回归确认历史 UP_TO_DATE 不能覆盖当前实际运行构建，服务页面在 1440／960／390 三种宽度均通过。没有重复启动已完成的检查。

本轮不执行实体设备安装、真实语音或生产诊断上传。隔离测试不能证明设备扬声器实际已发声，现场仍须确认设备播放结果。
