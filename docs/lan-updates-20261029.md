# 1.4.7 公司内网更新

用户问题：审核电脑没有代理时，从 GitHub 安装/更新过慢。原二进制只有 GitHub 来源，服务器改清单不能让旧二进制学会内网线路。

## 实现

- 顶部“版本与更新”新增自动、公司内网、GitHub 线路；默认自动优先固定公司服务器，显式公司内网不发 GitHub 请求。线路本机持久保留。
- 内网元数据三秒有界检查，直连不走代理、不跟随跳转；失败可重试或切换。自动回退 GitHub 会显示原因。失败清除旧可下载操作；已有校验包固定版本，防止显示与安装错位。
- GitHub 正式 Release 是发布来源，内网只提供同一份字节。元数据固定三平台、stable 版本、不可变官方资产身份；客户端下载地址按本机常量构造。包大小、SHA-256、Minisign、安装前缓存重验和审核落盘保护全部保留，没有开启 Tauri 不安全更新设置。
- 独立 `delta-viewer-update-mirror.service` 位于 10.1.41.17:17879，每五分钟同步，全三平台签名与安装器校验通过才切换，保留两版。下载失败/签名异常/同版本上游 metadata 变更不会删除当前可用缓存；修复已有缓存也先完整下载再替换。
- 部署代码和软件缓存存服务器本地盘 `~/.local/share/delta-viewer-update-service/`，不占 NAS。服务只提供 GET/HEAD 与 Range，不保存账号或审核数据，不重启其他业务服务。

## 使用

旧版首次从 http://10.1.41.17:17879/ 选择对应平台，正常保存、退出后安装 1.4.7 或更新版。以后登录后进入“版本与更新 → 下载线路 → 公司内网（无需代理）”，下载、稍后或保存并重启更新。

服务器仍需能取得 GitHub 正式包；审核电脑只需公司内网。同步中断继续提供已验证旧版，页面明确这是服务器缓存版本，不能承诺 GitHub 实时最新。没有公网镜像，离开公司网络需使用可达的 GitHub 线路。外层安装包维持 UNSIGNED，updater 完整性签名不等同于可信发布者签名。发布后不主动代管理员推送审核员更新提醒。

## 维护

`node scripts/install-update-mirror-linux.mjs` 只安装独立服务。代码变更后仅重启此服务。健康地址 `/healthz` 区分 ready/degraded/unavailable，显示真实最近成功时间；上游不通时排查服务器网络，不要求审核员配置代理。完整操作见 github-updates.md。
