# 同步异常与历史版本层级修复（1.3.6）

## 原因

截图中 sticky 同步提示的 z-index 为 35，自制历史版本遮罩仅为 20；提示位于 main-content 内，滚动后覆盖位于不同布局上下文的模态框。旧标注审计提示与新版审核操作队列提示独立渲染，同一次登录失效出现两条横幅，加上原始 AUTH_REQUIRED 错误。默认展开所有时间和错误又扩大了占用。

## 实现

历史版本采用原生 HTML dialog.showModal()，进入浏览器 top layer，自动约束焦点；Escape 和点击遮罩关闭，显式恢复先前焦点。异常状态位于当前测试或管理模式头部下方，仅一个组件、正常文档布局；主行显示摘要、真实操作事件数量及补传按钮，支持展开持久队列原始时间、未落盘数量、失败原因和原始错误。异常拒绝与未落盘丢失风险继续明确提示，正常及短暂排队不出现。未知保持未知，不推断 NAS 写入或工作台统计已完成。

标注审计队列与 SQLite 审核操作队列分别补传，Promise.allSettled 保证其中一类失败仍尝试另一类；任一失败继续保留提示。旧标注事件数不混入审核操作事件数量；额外待传单独说明。只收拢精确鉴权失效类别，其他业务错误沿用原错误入口。普通更新消息放右下角，原生模态框总在页面消息之上。未变更队列删除条件、事件 ID/时间、服务端统计、原始 QC 或 NAS 文件。

## 验证范围

隔离 App 复现 3497 条待传、两个队列登录失效及历史版本弹窗，在 1976×1280、1440×920、960×680、390×844 核对唯一提示、默认高度、可见补传控件、无横向溢出、模态 elementFromPoint 命中、Tab 焦点约束及关闭焦点恢复。原同步持久化回归继续覆盖网络断开/超时/503/未知错误、部分拒绝、磁盘失败、重启、换账号与补传成功。截图及运行证据在 ignored artifacts 中，发布和安装状态由交付记录注明，不能以代码完成代替实际安装。
