# 管理端统一写回 NAS · 1.5.8

管理员不必逐台远程点击原有确认按钮。管理模式的审核账号页新增独立统一写回区域，支持单账号、多选、全部和二次确认；用户中心保存指令，原电脑登录对应账号后在空闲时执行。此前用户中心仅持有操作事件与统计，无法凭统计生成完整人工结果，此边界保持。

## 范围和数据完整性

- 只从本机 SQLite 中按 service、username 选择已经提交的待写结论及骨架描述；动作草稿、云端 QC 工作区和非共享磁盘均排除。Windows UNC/映射盘、macOS/Linux 挂载表用缓存元数据识别共享路径，不查询 NAS 容量，不读取视频。未识别/断开挂载的路径仍保留，必要时原电脑手动处理。
- 每个指令在每台电脑建立事件 ID 快照，逐条复用原发布事务，原审核人、审核日期、事件 ID 与片段内容不重新生成。固定用户中心 HTTPS、角色门禁、当前账号/service 复核、TaskControl、队列 owner 锁、源 revision/hash/片段重叠门禁共同生效。
- 本次已经成功写入而执行回执丢失时，重启读取同一任务，通过持久 NAS 收据确认成功；没有收据不能仅凭队列消失宣称成功。新草稿替换了原事件时标明 changed，不覆盖新草稿。
- 满盘/目录不响应/本机落盘失败停止本次；冲突、非法片段分别保留，其他可写记录继续处理。失败需要处理原因后显式重发；部分失败不能被一次无关成功或其他电脑完成抹掉。
- 服务端只收有限状态、结果数量和固定失败分类，不接收源路径、异常原文、完整审核 JSON、视频或特殊标签。指令和回执 FULL/WAL 保存，不复用七天过期的版本提醒。

## 展示与限制

待写数来自各电脑最近真实上报，不从审核统计推算。本机队列不可读时显示未知。每台电脑独立展示等待上线/空闲、执行、完成和异常；已确认的终态不会被心跳覆盖。新结果需要再次下发，离线设备后续登录可接收最新指令。各电脑需升级至 1.5.8，旧版不支持自动执行；软件未运行或当前登录其他账号时无法访问该账号队列。完成只说明本次快照，不能承诺所有离线机器无积压或工作台已统计。

新版逐条执行，播放、正在审核操作、未存草稿和模态窗会延后，写回期间阻止退出/更新/导航；每条结束释放全局任务锁。管理员下发需确认，本次开发未向真实审核账号发出全部写回或软件更新提醒。

## 检查证据

本机 `pnpm check:full` 通过：282 个 Rust 库测试通过、17 个环境/私有样例测试 ignored，另有 3 个 CLI 测试；构建、Clippy、格式和服务器回归通过。原审核/片段完整回归包含 18 项逻辑和 46 项浏览器场景全部通过。新增隔离测试覆盖单个/多选/全部、越权、跨账号/设备、离线补送、服务重启、幂等、部分拒绝及旧请求、满盘/失联/冲突/重叠、新草稿替换、源写入后崩溃窗口、回执超时/补传、原审核信息和设备数量未知。桌面、960 和 390 宽度检查按钮、模态窗口和文字可见。

部署方案为使用独立 Viewer 用户中心发布目录，更新既有用户中心单元；原 D1-pipeline 已校验发布目录保持原样。保留现场 output provenance 扩展，运行身份明确记录 Viewer 版本、提交及基础流水线身份，继续验证源码清单；证书、service ID、账号、审核和领取库保持，备份位于私有状态目录。工作台、上传、云 QC、镜像及 NAS 服务不重启，不调整 RAID。三平台构建与 Windows 现场验收以正式流水线及发布后的交付报告为准；本报告的本机通过不能代替三平台安装验收，历史缺失审核记录未恢复。
