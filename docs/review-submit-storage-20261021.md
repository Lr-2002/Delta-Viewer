# 2026-10-21 审核提交长等待与共享存储满盘调查（1.1.9）

## 结论与证据

提交审核结论的文件写入目标是数据目录，不是用户中心。当前数据位于 `10.1.40.2` 的 Datasets 共享，底层为 `/volume8`。现场只读检查显示该卷 58 TiB 级容量、可用块与空闲块均为 0；当时负载约 72.56，其中 I/O 等待约 71.87、CPU 约 0.69。容量与 I/O 故障足以造成所有使用该卷的客户端共同长等待、写入失败。

在原始 session 之外建立独立、唯一命名的小文件验证实际写入，结束后只移除本次创建的测试文件：

| 隔离测试 | 结果 | 耗时 |
| --- | --- | --- |
| 数十字节写入并 fsync | 成功 | 4.985 秒 |
| 64 KiB 写入并 fsync | errno 28 / No space left on device | 27.477 秒 |
| 1 MiB 写入并 fsync | errno 28 / No space left on device | 0.050 秒 |

小文件偶尔成功不能证明卷正常；64 KiB 已复现长等待后 ENOSPC。共享目录仍可能存在已分配文件内部空间与文件系统元数据预留，所以不以数十字节写成功否定满盘。测试没有修改媒体、机标、真实 `description.json` 或 `session.json.qc`。

当前固定证书配置的用户中心为 `https://10.1.41.17:17880`，与 NAS 是不同主机。使用配置内信任证书、禁用公网代理，连续三次 `/healthz` 均 HTTP 200 / ready，约 2–4 毫秒，service ID 与客户端一致。未重启用户中心、工作台、NAS 统计或上传服务。Windows PowerShell 默认不信任该私有证书的检查结果不能当作 Viewer TLS 故障；Viewer 使用导入的固定证书。

目标 Windows 当前进程为 1.1.8，正常响应。截图只有“正在保存…”与禁用决策按钮，没有网络错误全文；无法从截图确认每台审核电脑的系统错误原文，不能断言所有网络异常都只有一个原因。但当前卷满与真实 ENOSPC 已独立复现，必须处理。

## 软件链路与修复

- `save_machine_review` 的身份检查只读取当前进程已登录会话，不向用户中心发起请求。结论保存前后只等待操作事件写入本机 SQLite，不等待上传。已登录会话下用户中心临时不可用不应阻断结论保存；NAS 断开或满盘仍无法写共享结论，不能称为完全离线存储。
- 旧版仅在保存前检查目录是否存在，没有容量检查；真正写文件、fsync 时才遭遇 NAS 的长延迟与底层错误。界面一直只有“正在保存”，没有说明保存位置和恢复办法。
- 新版单条审核及未审核不通过在真正保存前启动本应用的只读子进程，确认实际写入目录可访问、至少 32 MiB 临时空间。使用系统挂载路径与 `fs2` 查询，不接入 NAS 协议、不写探测文件、不扫描媒体。5 秒无响应终止只读检查，尚未开始审核写入；未知空间查询失败单独说明，不冒充断网。Linux GVFS 路径按既有 CIFS 写入目录映射检查。
- 32 MiB 用于两份最多 8 MiB JSON partial 及元数据预留，是保存保护阈值，不是 NAS 长期可用容量建议，也不保证检查之后空间不会被其他上传占用。
- 原子写入途中遇到满盘、权限、超时等错误，显示稳定错误码、具体位置、原系统原因和重试指引。其他 I/O 原因仍明确未知，不宣称用户中心故障。
- 超过 8 秒显示持续等待说明，明确还未确认提交成功。原生写入没有被前端计时器遗弃，不会偷偷继续保存后再允许重复提交。锁、真实并发保护、`sync_all`、回读和原子替换保持不变。
- 按用户新要求，完整审核结果与原始事件 ID/发生时间先进入本机 SQLite 待写队列（WAL、synchronous=FULL），按服务与账号隔离。单条审核、批量和整文件夹不通过适用；本机持久化成功后可继续下一条，失败保持页面和应急草稿，不虚称已保存。后续编辑保留首次共享基线，旧本机内容归档；相同数据不能以另一来源或批量重复叠加。
- 主界面持续展示当前账号真实待写结果条数和每条最初本机保存时间。后台每 30 秒检查第一个待写目录的容量和连接；恢复后弹窗提醒，用户确认才开始依次处理全部条目，每一条写前分别检查。第一个目录恢复不代表其他卷均恢复。明细最多 200 条，总量用数据库准确计数，写回逐条读取完整 JSON，避免一次加载大量动作文本。稍后可保留待写结果，重启后登录同一账号继续。
- 写回使用已有共享锁、原子保存及回读校验。普通审核在锁内校验首次机标、人工输出哈希/修订及 QC 字节基线；批量仅处理仍未审核条目，已审核结果保留。冲突不会覆盖，保留本机记录并提示核对；该版本不提供强制覆盖冲突入口。存储恢复、手动检查或其他条目成功不能清除未解决条目的失败。
- 普通提交从开始就使用稳定提交 ID/发生时间；共享成功而本机确认失败时可以识别相同结果并幂等确认，不重复结论。共享写入确认后，先把原审计事件写入本机事件队列，再删除对应待写结果。用户中心不可用仍可保留事件等待补传。写回期间占用任务槽并阻止退出/更新，关闭窗口有保护。

## 恢复条件与边界

软件更新可让可读取的数据继续本机审核，不会凭空增加 NAS 容量。NAS 共享写入仍需管理员释放空间或扩容；未获指定清理范围，不删除数据、预览或备份，不影响上传。未加载的视频仍需源目录可读，未声称完整离线媒体缓存。本机结果不计共享任务中心进度；写回 NAS 后仍需服务器读取 QC，用户中心已接收也不能等同工作台统计完成。

本次不补造历史审核事件，不宣称历史缺失记录已恢复，不修改时长统计：通过和不通过原始时长均应计入；有效耗时仍按真实操作、扣除超过 120 秒无操作段，心跳不作为有效操作。重启/卸载前请区分已经持久化与尚未保存：持久化记录可重启保留，卸载时不得清理应用数据。

## 验证与发布边界

已完成 TypeScript/Vite production build、Rust format、Clippy `-D warnings` 和 Rust 自动回归：204 项常规测试及 3 项附加测试通过，14 项依赖已删除私有样例的历史测试按既定规则忽略。其中新增本机队列重启/账号隔离、首次基线与旧内容归档、共享冲突不覆盖、稳定事件幂等、普通和批量部分提交恢复回归。数据库关闭再打开验证本机队列恢复；容量查询注入 0 字节、未知容量和超时，不依赖真实原始数据写入。

浏览器回归覆盖本机也写入失败时阻止完成、暂存后前进且不虚报共享通过、批量满盘暂存与重复操作保护、恢复后需明确确认、写回失败不被刷新清除、部分冲突、成功隐藏提示、账号切换及 1440/960/390 像素布局。审核操作事件持久性、失败重试和原有校对交互回归同时执行。

Linux 原生只读容量 helper 对本地目录返回 0，对不存在目录返回 2，耗时约 0.02 秒；NAS 满卷返回 3 的现场检查为前文所述只读/隔离证据。检查不会写探测文件。所有写入回归只使用隔离目录，不修改真实审核结论或上传测试事件。

版本与中文摘要同步为 1.1.9。三平台原生安装/启动验收以 GitHub Release 附带报告为准；目标 Windows 的实际安装、本机暂存、真实进程重启与确认写回证据随桌面交付保存到测试产物目录。浏览器和 Linux 检查不替代目标 Windows 验收。
