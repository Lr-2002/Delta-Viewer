# 高倍速短暂解码等待（1.12.4）

用户要求长视频也能流畅倍速，并再次明确新版应从软件“版本与更新”直接检查、下载和安装。1.12.3已正式发布；当前原生窗口检查到1.12.3且显示无需更新。此前旧1.11.4模块下载测试是诊断程序，不冒充实际旧窗口按钮。新版本正式可用后继续在保留的1.12.3里检查和下载，不代安装或清登录。

## 复现

同一Windows 11、Intel i5-13420H/UHD、16GB机器，1.12.3真实七路，主相机3840×2160、另六路为1280×720/848×800/1920×1080；全部H.264且使用D3D11VideoDecoder。只播放本人已领取的约16秒录制，不写审核。顺序短时观察：4倍约4.06秒推进14.88媒体秒；6倍约2.27秒只推进4.19秒；8倍约1.77秒只推进2.16秒。后两组各约50次waiting，分别129/107次pause和88/94次ratechange；媒体数据始终仍有约11–14秒缓冲，没有网络/媒体错误。

waiting与canplay相隔数毫秒，有些waiting被处理时已经readyState=4。旧处理不重核状态即暂停所有健康同伴，并将缺帧镜头降到2倍；随后立即恢复所选倍速，引发下一轮解码波动和全组启停。该实测支持客户端放大瞬态等待这一原因，不能声称所有慢网、所有硬件或长视频卡顿均同因。样本已全部缓冲，不能用于证明网络吞吐提升。

## 修复

- waiting处理时重新检查readyState、ended与seeking；已经恢复的迟到事件不改变播放。
- 大于3倍且当前缓冲区含至少四分之一秒真实播放量时，合并极短解码波动；等待上限为`min(30,120/speed)`毫秒，即最多0.12媒体秒。重复事件不能刷新截止。
- 若仍未恢复，沿用既有七路共同暂停、缺帧镜头恢复及缓冲储备；压缩数据不足或1–3倍真实waiting仍立即处理。
- canplay、暂停、seek、改速、解绑、dispose取消相应计时；世代和元素身份复核阻止旧回调影响新源。
- 不新增seek、降分辨率、隐藏相机、转码、落盘缓存或后台额外解码器。

## 验证和边界

`scripts/outbound-playback.test.mjs`新增三个必要回归：迟到waiting、短暂/持续解码间隙、网络缺数据与迟到回调取消。修复前新增项均失败，修复后连同既有高倍速恢复回归通过。持续缺数据、暂停/定位及旧1–3倍行为继续验证。
