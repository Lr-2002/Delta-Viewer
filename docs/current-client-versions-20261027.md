# 当前版本与版本日志（1.3.8）

## 已核对事实

2026-10-27 13:50（北京时间）只读检查用户中心：lvxin 的 review-audit.sqlite 持续收到 play、seek、scroll、片段修改和 heartbeat，发生及服务端接收时间相近；client-presence.sqlite 的 clients 表没有 lvxin 的记录。它们是两个独立协议，审核统计不能证明版本上报成功。旧客户端的用户中心 User-Agent 固定为 Delta-Viewer-User-Center/1，没有应用版本；事件也没有可靠软件版本字段，不能从操作内容反推具体版本。

版本上报组件首次在 1.3.3 加入，1.3.0 标签中不存在。未上报可能是旧客户端或独立上报链路失败，未取得对应电脑前不能确认为某个具体版本。已向用户询问 lvxin 的电脑 IP/机器名，待现场核对；没有连接或升级未知审核员电脑、没有伪造版本或将未上报视作未工作。

## 修复

旧客户端实例 ID 的 key 包含 APP_VERSION，每次升级会被服务器当成另一台设备，从而在一行中出现多个历史版本。1.3.8 使用跨升级的 v2 key，优先复用当前或最近旧版本键中的 UUID，不删除旧键、原设备记录、账号资料或审核数据。回到前台、聚焦及恢复网络立即重报，继续保持 15 秒轮询及同一账号提醒确认。上报失败不能阻止审核，也不增加有效审核时间。

账号列表每人仅显示一个新鲜在线上报的版本，选择最近的真实上报而非最高版本；其他不同在线版本有数量提示，以免隐藏账号多端使用。没有在线报告、缓存过期或刷新失败显示“当前版本未确认”，不拿离线记录假装当前版本。设备最近上报、时间与未知原因置于每人“版本日志”原生模态框，Escape 关闭、焦点返回、内容独立滚动；明确它是服务器保留的设备最近记录，不宣称为完整升级历史。

本版不更改服务端协议或业务统计，无须重启任何后台服务，NAS QC 和人工 JSON 不变。旧于 1.3.3 的审核端需手动安装支持协议的新版后，才可能上报和接收推送；单纯修改管理页不能替其生成真实版本。
