# 1.1.1 GitHub 更新稳定性修复与复查

## 问题定位

1.0.63 截图已经包含官方 `v1.1.0/latest.json` 地址，因此最新版本发现成功，失败发生在更新清单网络读取阶段，尚未开始安装包下载或安装。它不是版本号比较失败，也不能根据这条通用错误判断审核数据损坏。忙碌提示只禁止下载/安装，不禁止后台检查。

对目标 Windows 主机的只读检查发现系统静态代理已启用；没有公开其地址或凭据。HTTP 库关闭默认特性后未重新启用 `system-proxy`，实际构建特性中也没有该项，所以旧版会忽略 Windows/macOS 的系统代理设置。依据见 [reqwest 官方特性说明](https://docs.rs/reqwest/0.13.4/reqwest/#optional-features)。1.1.0 继承相同客户端实现。

排查时，官方 API、最新正式版跳转和 v1.1.0 清单都可访问；直连与系统代理各三次清单请求均返回 200。旧错误只保留了请求地址，没有下层连接、TLS 或超时原因，无法唯一追溯截图那一次网络失败；不将当前可复现的代理兼容缺陷冒充为已证明的唯一历史原因。

另有两项会放大短暂波动：读取清单没有自动重试；应用验证清单后，原生更新插件还会再联网读取一次，任一请求失败都会使检查失败。

## 修改

- 公网更新启用系统代理；局域网身份和审核上传固定证书直连。
- 公共 GET/HEAD 请求对可恢复网络错误做有上限的重试，失败响应不保存、不拼接；取消下载能够中断等待。证书验证与官方 HTTPS 重定向限制保持有效。
- 同次检查将唯一完整、验证后的清单交给原生安装器复用；继续校验完整平台集合、精确正式版本、官方 URL、包大小、SHA-256 和 Minisign。
- 错误按查询版本、读取清单、下载包分别显示，区分超时、HTTP、连接、证书和未知原因；不显示敏感代理或 CDN 查询参数。
- 版本四处统一为 1.1.1，更新中文摘要；原检查/主动下载/保存后安装的流程和审核保护保留。

## 复查与验收方法

检查实现必须同时审查：重试边界与取消、完整响应和大小限制、原生插件从已验证清单构造安装对象、系统代理对局域网用户中心的隔离、严格签名与缓存校验、工作区保存及退出保护。离线用本地隔离 HTTP 服务模拟 503、连接关闭、超时、半途断流、404/403、越界响应和越权跳转，避免用线上故障作为唯一证据。

原生 Windows workflow 运行相同网络回归；公开最新正式清单与当前平台包额外做显式联网下载验签。完整三平台发布后再确认官方最新版本发现及目标机安装/桌面窗口，具体执行结果在本次交付中补充。

本机验收已通过：`check:full`（174 项 Rust 单元测试及 3 项 CLI 测试，14 项环境/联网测试默认忽略；含格式、Clippy 与原生 debug 构建）、3 项更新交互浏览器回归、原生插件清单复用测试、6 项发布脚本回归和 15 页 Wiki 链接检查。显式联网测试通过当前正式 v1.1.0 的版本发现、Linux 更新包完整下载、SHA-256 与 Minisign 验证，没有安装或操作源数据。

手动代码复查已完成，重点确认无业务凭据进入 GitHub 请求、用户中心保持直连、重试不复用半份字节、取消可打断等候、签名和缓存校验未削弱。复查发现并修正测试取消时机依赖和诊断程序可能混入发布输入的问题；最终发布仅汇总 `release-*` 三平台正式资产，诊断程序作为独立临时 Actions artifact，不进入公开安装集合。未来新增正式包仍必须通过同样校验，不作“任何网络环境均成功”的承诺。

## 限制与旧版本迁移

软件可以修复代理兼容性、降低瞬时故障影响并显示真实错误，不能保证 GitHub 或 CDN 不可达时仍能联网更新。若旧版始终无法检查，可正常保存退出后手动安装新正式包一次；不覆盖历史 Release、不改原审核结论、不重启工作台或用户中心。
