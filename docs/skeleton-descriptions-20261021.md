# 1.2.2 骨架片段描述与后续目录改名

用户确认骨架片段只作为描述入口，不设置审核功能。复用现有编辑器，双标签切换仅装载一个编辑器以避免快捷键冲突；保存进行中或失败时阻止切换。动作来源菜单仅在动作通道展示，骨架没有机标依赖。

骨架使用相同视频实际帧号，初次片段为空；恢复已有 skeleton.description.json。新增、切割、删除和恢复、边界联动、回放、数字快捷键和自定义排序标签沿用原编辑器。六个预设只在该账号首次没有骨架标签库时初始化，用户删除后不会被强制补回。

公开文件为 schema_version 4 的 episode_results/annotations，零基左闭右开，实际删除/新增写入数组，无 _human_review。技术状态位于 .skeleton.description.review-state.json，绑定内容哈希；本机草稿记住比较基线，其他客户端或外部写入后拒绝覆盖。源端原子 partial/同步/回读保护沿用，NAS 失败使用账号隔离 SQLite 队列；骨架和动作分别存储，确认写回保持原事件 ID 和发生时间。骨架没有 QC 写入，也不写动作结果、共享账号结论或通过/不通过事件。

现场 1.2.1 原生验证：三种来源的通过/不通过、新增/删除、精简人工审核信息已写入并重启重载，机标 SHA-256 未变。但现场目录已在本轮期间再次改成 D1-Daily、D1-Validation、D1-Yiqi 及 D1-Motion caption，固定旧分组名称导致新版组在浅索引中误识别成批次。1.2.2 同时覆盖这些变体、连续映射与 Skeleton 子批次，不能把 1.2.1 描述为已适配后续所有改名。服务器独立 layout.json 已补齐 164 条明确完成迁移，所有最终目标只读验证存在；不修改原数据、不重启服务。

验证覆盖：无机标初始化、与动作互不污染、增删及新主机重开、缺技术文件恢复、外部改写冲突、与 QC 损坏隔离；两通道离线同时暂存、补写失败保留、确认补写及中断重试幂等、账号隔离；连续目录改名与独立批次键。浏览器覆盖六个预置、自定义、数字键、切换恢复、无审核按钮、1440/960/390 布局。最终三平台及目标机验证以发布产物报告为准。

本机验收结果：`pnpm check:full` 通过（221 项 Rust 单元及 3 项目标验证，另 15 项既有人工条件测试未运行），31 项审核页面回归通过，任务中心回归、待写回提示、并发操作、4 项登录定位与对话框恢复、15 页 Wiki 链接检查通过。截图覆盖 1440×920、960×920、390×920。正式安装包和目标 Windows 继续使用同一版本提交验证，不以此替代原生验收。
