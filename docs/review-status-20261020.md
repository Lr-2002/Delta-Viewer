# 1.1.8 当前审核结论与历史状态分离

## 调查结果

反馈界面中的“审核通过”来自历史 `revisionLabel`，“已通过”来自 `ReviewState.status`，二者此前均没有核对当前目录根级 `session.json.qc`。本机草稿以路径缓存；共享人工结果不存在时，加载流程仍恢复草稿的历史 `published/status`，可以在当前 QC 待审核时显示已通过。共享人工文件历史状态与根 QC 不一致也会误导。

只读检查反馈目录：根 session 无 qc，根目录无 description，机标无 `_human_review`。这证明当前源目录不能据此认定人工通过；尚未取得反馈审核员电脑对应的旧草稿，因此不能断言该电脑历史文件何时被移走、由谁操作。目录机标来源核验不代表人工审核。

## 修复

- IPC 增加只用于显示的 `ReviewView`，独立读取当前根 QC；编辑用 `ReviewState` 保持原契约。显示字段不写入草稿、description 或源机标，避免旧客户端的严格结构解析受影响。
- 当前结论只认 QC；空白、缺失、待审核、未审核显示待审核。不通过原因也取当前 QC。异常值、JSON 损坏或 I/O 失败显示未知与重新读取指引，不能沿用历史成功。
- 没有共享结果哈希的本机草稿不能显示已发布，但片段、原 revision、历史状态仍完整保留。
- 版本行显示“历史修订（非当前结论）”，完整摘要保留在悬浮提示中；重新读取先清除旧显示，异步切换仍由账号/目录/来源 key 和 active 检查隔离。
- 不修改原审核结论、审计队列、媒体和机标，不触发全量扫描、不重启用户中心或工作台。

## 验证范围

隔离回归覆盖：带/不带输出哈希的过期通过草稿、其他账号历史草稿、共享历史通过结果但当前 QC 待审核、根 QC 外部变化、通过/不通过及中文/英文冒号原因、异常 QC/JSON/I/O、历史修订与当前结论分离、重新读取，以及 1440/960/390 像素视口。原始源结论与机标字节保持不变。

正式构建、CI、三平台安装及目标 Windows 结果以对应 PR 和交付报告为准；本报告不提前声明尚未执行的现场检查通过。没有恢复历史缺失审计事件。

## 同批反馈：批量不通过“审核内容已改变”

截图显示 61 条待处理，进行时成功 2、跳过 5、失败 43、未执行 11，不能把这个中途截图当最终结算。只读抽查其中 289/290/292/293：根 QC 均不存在，根 description 均不存在，未对这些记录提交审核结论。

原流程先读取当前人工内容，但 `rebased` 又把“磁盘旧草稿的 output hash”与当前共享结果比较；共享文件已移走或其他电脑此前已修改时，旧草稿永远不同。旧 metadata 的 source hash 与新机标也会被当作本次操作期间的变化，导致重新打开/刷新后仍重复报错。这些分支已用隔离数据复现；没有取得该审核员电脑的旧草稿，因此不能断言 43 条均由同一分支引起。

改为传递本次预检的共享输出哈希与当前机标哈希，锁内仍比较最新修订、共享字节及 QC。旧缓存不再单独触发冲突；准备之后即使未增加 revision，但人工文件字节发生变化，仍拒绝覆盖。源机标改变、已完成 QC、已完成共享人工结果与另一个进程持锁的保护保留。孤立本机旧通过/不通过草稿不再排除源端待审核条目，片段文字和边界完整保留。新增旧输出缺失、跨电脑已改文字、旧机标哈希、真实并发变化与完成状态保留回归。

本次没有代替审核员执行源批次的批量不通过。升级后由审核员重新选择当前未审核项并确认提交，已成功/已审核项仍会安全跳过。
