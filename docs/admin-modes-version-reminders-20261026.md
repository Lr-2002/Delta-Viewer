# admin 双模式、客户端版本与更新提醒（1.3.3）

## 行为与边界

admin 保留既有用户名、密码哈希、operator 身份及历史审核记录，只新增服务器维护的 `managementAccess: true`。登录的公开身份回传 `canManage`，所有原管理 IPC 与服务端管理 API 核验该权限。注册、个人资料接口不能授予权限，不按用户名 admin 自动授权。按用户确认停用原管理员 yangshuoniubi，保留其历史身份及全部原记录，不把历史操作改署 admin。

admin 登录默认测试模式，顶部管理模式进入原审核监管，测试模式返回已载入的审核区。编辑器保留挂载及本机草稿，管理期间暂停视频与隐藏编辑器的全局快捷键、结束当前审核会话，回到测试时重新开始会话；管理操作不算审核交互。保存或长任务尚未完成时不切换。所有持久审核队列、NAS 发布和退出保护沿用原逻辑。

账号页分别展示每台实例的运行版本、平台、最近服务器接收时间和在线状态。客户端通过现有固定证书 HTTPS 每 15 秒独立上报；原生端写入编译版本和平台，前端不能传入任意版本。在线同时需要 90 秒内上报及有效登录会话；服务重启后的持久版本先显示离线，直到重新上报。未上报保持未知，取数失败保留版本并说明在线状态未知。每账号最多展示最近 16 个实例、保留 30 天历史；随机本机实例 ID 不包含机器名、用户路径或源数据。

一键全部面向当前启用且非发送者账号；多选面向所选有效账号；行内单个按钮发送该账号。服务端 SQLite WAL + FULL 保存提醒，相同账号尚未处理时合并推送，7 天过期。弹窗在支持版本的客户端轮询后出现，不抢焦点、不自动消失，可查看更新或稍后处理；确认按账号隔离并在客户端暂存，断网后重试，别人不能确认此账号的提醒。旧版无法接收新协议，需先手动升级。管理页明确说明离线待送与旧版限制。

推送不指定下载地址、安装版本或二进制，只打开既有官方 GitHub 检查入口，继续由用户下载、验签并确认安装，不强制升级。心跳与提醒不写入审核审计、不贡献有效耗时。NAS QC、原描述、通过/不通过时长与 120 秒空闲扣除不变。

## 隔离验证

`pnpm test:user-center` 包含真实隔离 HTTPS/SQLite 整合测试：授权前 admin 无管理权限、保留原密码和普通审核身份、停用旧账号、管理 API 门禁、不能删除/暂停管理账号、单个/多选/全部、账号隔离、会话退出、服务重启后补送。独立存储测试覆盖多设备、过期/未上报、失效会话、去重、重复确认、越权确认、7 天过期、实例数量上限及无效输入；原审核队列/统计回归一并运行。

`pnpm test:client-management:browser` 覆盖实际 App 中模式切换、账号页单个/多选/全部、版本刷新失败保持未知、1440/960/390 视口、提醒持续显示、确认失败及重载补传、账号切换、查看官方更新及保留输入。相关更新提示、动作编辑、操作归属及完整发布门禁仍需通过；截图和测试输出仅存 ignored artifacts，不提交。

## 部署

使用现有用户中心 systemd 单元短暂停止后，运行：

```bash
node scripts/consolidate-admin-account.mjs --data-root USER_CENTER_DATA --from yangshuoniubi --to admin --offline-confirmed
```

脚本以 0600 权限保存原账号文件的不可覆盖备份，仅原子更新目标的 managementAccess 与旧管理员的 accountStatus，回读检查，原密码哈希不变。必须确认服务已停止，防止服务同时写账号文件。部署保留用户中心配置、证书、service ID、全部原账号状态和审核/领取库，保留旧可执行版本用于回退；不修改或重启工作台、上传和 NAS 统计服务。用户中心短暂停止使会话失效，审核员用原账号密码重新登录；本机审核草稿与待传队列不清空。服务升级不改变旧版的审核/领取协议。
