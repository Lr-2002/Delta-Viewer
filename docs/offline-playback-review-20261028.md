# 1.4.3 离线模式、骨架同步和本机审核结论修复

日期：2026-10-28。版本：1.4.3。现场只读排查与隔离数据测试，不代替审核员处理真实任务。

## 不通过报错与侧栏状态

截图的 `本机不通过 · 待写回 NAS` 表示本机持久队列已有结论，不表示共享目录写入成功。2026-10-28 从目标 Windows 的实际桌面会话调用 GetDiskFreeSpaceEx，确认 `\\10.1.40.2\Datasets\Delta-D1\D1-Daily\2026-09-05-Dish Washer` 所在卷可用及空闲空间均为 **0 字节**（总容量 63,331,842,916,352 字节）。这会阻止共享 JSON 写入，客户端可先持久保存本机结论。

另有客户端逻辑问题，已在隔离环境复现：

1. 批量不通过在 NAS 不可写时保存无具体机标来源的 `onlyPending` 结论；单条编辑器按 Flash 等具体来源读取，未恢复该结论。再次自动保存时触发其他来源已有结论的保护，却把业务冲突包成 `SOURCE_REVIEW_LOCAL_STORAGE`，造成“本机也没存好”的误解。
2. 再次批量提交把已有本机结论视为失败（`SOURCE_REVIEW_EXISTS`），而不是跳过；侧栏与编辑器底部取用的状态也不同。

修复后，单条打开可跨来源恢复批量结论，并保留当前机标片段，不以批量占位的空数组覆盖。已存在的本机结论只读显示“本机通过/不通过 · 待写回”，等待通过原待写回入口处理；重复批量操作跳过已有结论，明确“保留原结果”。未审核草稿不能覆盖其他来源已提交的结论。多份本机结论明确显示冲突并全部保留，不任意选择或删除；业务冲突单独报 `SOURCE_REVIEW_CONFLICT`，真正的本机保存失败仍保留独立错误。

原事件 ID、提交时间、原因和未确认队列保持。用户中心确认接收只代表接收，不等于工作台统计完成或 NAS 已写入。NAS 待写问题仍须释放空间或扩容，软件不会自动删除源数据。

截图审核员为 1111，当前目标桌面登录 admin；只读复制的当前队列有 4 条 admin 待写记录，没有截图两条的匹配行。因此**未独立核实截图全部 54 条，也不声称它们已写回或恢复**。没有修改真实审核结论或重启工作台、用户中心、上传服务。

## 骨架落后画面

只读样例 `2026-09-03-Fridge/Fridge_051` 的 `smpl_joints` 与流水线对 `raw_smpl_joints` 执行因果 EKF 的输出逐值一致。整段手臂相关性约滞后 17 帧（0.57 秒），但滞后随动作变化，不能固定提前 17 帧补偿。在 cam0 第 501 帧，图像和原始估计的手已近头部，滤波结果仍近腰部。

现在优先选择有效 `raw_smpl_joints`，缺少或无效时兼容原数组，界面标注“原始同帧估计 / 滤波估计”。使用所选字段自己的索引；已知流水线的 cam0 编码索引通过与播放器相同的采集时钟映射，保留原 ID 和小数时间位置。非法或非单调索引明确报错，不猜测拉伸。独立动作播放器的骨架直接跟随主相机实际呈现帧，避免额外 React 状态延迟。没有修改源 NPZ，也不凭空恢复缺失的世界轨迹或地面标定。

## 多路播放

副相机每 250 毫秒检查小漂移，有限调整播放速率（最多 ±8%）追齐；偏差大于 0.75 秒且目标已有缓冲才硬定位，减少反复 seek。任一路缺缓冲时共同暂停、恢复前对齐、暂停和拖动期间冻结共享时间轴的规则保留。减少骨架重复采样。

硬解仍由系统、WebView 和驱动协商；不能承诺任意视频、介质和硬件都五秒进入或永不卡顿。旧滤波数据没有原始关节时仍可能含算法滞后。

## 离线模式使用

登录页点击“离线模式”，无需账号、联网或用户中心配置；已有配置缺失/损坏也可进入。选择本地数据后可回放、检查、编辑动作及骨架、通过/不通过、导出。修改动作仍只保存本机草稿，显式点击通过才发布修改后的人工结果。

离线标注以“离线本机”署名，使用独立 `offline-local` 数据目录和队列，不接入用户中心、公司效率、设备上报、云 QC 或自动更新，不会在以后登录公司账号时混入补传。离线不授予管理员权限。普通本地批次支持更名；共享审核批次更名仍须登录核对领取归属，联网账号的云端缓存不能离线编辑。切回联网工作区重新登录。
