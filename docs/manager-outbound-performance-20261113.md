# 外发审核播放与界面验证（2026-11-13）

## 现象与对照

在目标 Windows 的正式 1.9.8 应用只读检查同一条已领取录制：五路视频来自交付平台媒体接口，不经过 NAS；主相机 3840×2160，两路 1280×720、两路 848×800，时长约 6.93 秒。五路均已完整缓冲。电脑 i5-13420H、16 GB 内存，空闲约 5 GB。

原播放逻辑观察 5.4 秒，主路仅推进约 1.24 秒，副相机反复 seeking／waiting。保持同样视频、网络和主机，临时隔离旧同步事件后观察 4 秒，五路均推进约 4.02 秒且零丢帧。现场暂停点和播放状态已恢复，没有领取任务或提交结论。这证明已缓冲后的卡顿来自前端重复定位；不能据此声称全部数据、主机和网络都没有其他瓶颈。

原生 HTTP Range 另测读取首个 1 MiB：两路均返回 206，响应头等待约 5.19／8.66 秒，正文传输约 0.24／0.23 秒。平台首响应等待与播放同步问题分别记录。不能把下载完成或浏览器夹具通过等同于现场最终版本通过。

## 实现

- 独立统一播放控制器，连续播放只轻微调速，媒体事件不发出 seek；主动播放／定位才对齐。
- 真实 waiting 暂停全组，全部就绪恢复；暂停、离开、切录制使旧播放意图失效。
- 视频票据最多四路并发，逐路创建媒体元素，慢一路不阻塞其他画面；所有相机就绪前保持结论门禁。
- 外发 HTTP 客户端按固定完整配置复用 TLS，每次仍核对当前登录会话，不缓存令牌或业务响应。
- 紧凑录制队列、进度、五／七路适配网格、单一播放控制与固定结论操作区；中文、主题一致、原画质和全部分段保持。
