# 1.0.61 审核操作记录持久化与异常提示

审核操作继续写入本机 SQLite 待传队列，按用户中心和账号隔离。事件从异步生成目录标识之前起就保留原始 ID、时间和会话归属；迁移旧 localStorage 队列期间新增的操作也必须随保存屏障一起落盘。

审核结论提交前先保存此前操作，提交成功后等待结论事件落盘再进入下一条。如果结论已保存但操作记录保存失败，界面保持当前数据，重试只处理操作记录，不重复提交结论。更新和退出登录前暂停产生事件并等待落盘；失败恢复当前审核会话。

同步正常及短暂排队时不显示横幅；出现本机保存失败、上传错误、超过 30 秒的积压或异常记录时持续提示。未落盘有丢失风险时红色显示，已经保存在本机但待上传时橙色显示。后台持续补传，恢复后自动隐藏；可以手动重试，鉴权失效时可以续期当前账号登录。窄屏保留按钮文字和输入框。

待传数量的单位是操作事件，包含未落盘及服务端拒绝记录。最早待传时间来自记录原始时间；最近同步时间只在服务端确认且本机删除对应事件的同一数据库事务中保存。旧记录时间缺失、旧缓存尚有去重歧义时保持未知。服务端拒绝的事件保留原因，其他事件成功不会清除其状态；未确认事件不删除。

用户中心已接收与工作台统计完成是不同状态。该修复不会恢复已经丢失的历史操作，也不会补造审核开始时间或修改原始审核结论；不改变工作台时长统计规则。操作系统强制结束或断电前仍未提交的内存事件不在保证范围内。

## 验证范围

隔离回归覆盖旧队列迁移并发、异步目录标识和磁盘失败、审核结论提交后落盘失败、更新和退出屏障、网络断开、超时、服务端异常、登录失效、部分拒绝、重启积压、账号隔离、正常隐藏及恢复后隐藏，以及桌面和窄屏布局。测试使用临时数据库和合成事件，不向正式服务写入测试记录。

发布前执行 `pnpm check:full`、`pnpm test:proofreading` 和 `pnpm test:review-audit:browser`。Windows 桌面预览原生构建及可见窗口启动已验证；正式三平台安装器由 Release workflow 进行构建、安装与启动检查，只有完整集合成功后才发布。浏览器模拟故障不等同于三平台真实磁盘故障验收。
