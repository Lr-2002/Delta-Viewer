# 设备页面与 OTA 源站提示验证（1.10.2）

日期：2026-11-16。此前正式版本为 1.10.1；本次保留三模式 SSH 升级、售后日志、最新版本识别及既有审核功能。

## 原因与行为

现场只读核对时，D1 状态网页可访问，固定 OTA 源站的网页和 SSH 端口均超时；用户随后确认源站故障。因此版本检查失败不能解释为 IP 连接方式不支持升级，也不能将设备显示为断连。本轮没有修改、部署或重启源站服务。

此前检查最新版本还会预先下载全部五个发布文件，包括约 30 MiB 的安装包，增加等待。现在只获取通道原文、带 generation 的配对签名、manifest 原文及签名，核对清单大小、摘要、schema、资源描述与版本／发布编号／密钥编号／防回退序号一致性。已配置受信任公钥时按原始字节验签；当前配置没有正式发布公钥，不声称完成发布者验签。

仅在确认升级后，设备优先下载预览中锁定的源站和版本制品路径并独立核对完整包。设备不能下载时，管理端才下载同一 Debian 包、核对大小及 SHA-256，再通过 SSH 发送。不会再次解析“最新”并拼接另一版本，也不为 SSH 安装下载无关的 changelog 正文。

源站错误分为超时 `OTA_SOURCE_TIMEOUT`、无法连接 `OTA_SOURCE_UNREACHABLE`、传输中断 `OTA_SOURCE_INTERRUPTED` 及具体 HTTP 状态。界面说明失败环节和操作建议，技术码折叠显示。检查开始清除旧预览，失败后不保留可用的旧升级按钮，设备连接状态保持独立。

元数据连接超时为 5 秒、单次总时限 15 秒；安装包总时限 600 秒、读取空闲时限 30 秒。短暂连接／传输故障及 HTTP 502／503／504 最多重试一次，间隔 250 ms；404、大小、摘要或签名错误不重试。请求和响应流均响应取消。

## 页面布局

设备页面与应用升级使用独立标签，iframe 和升级组件保持挂载，切换保留未提交输入。原生升级入口转到宿主升级标签，不触发安装。原生设备页保留既有脚本、字段及经固定协议确认的配置操作，桌面内容上限 1240 px，概览置顶、配置双列，窄窗口单列。当前可见面板独立滚动，不再把固定高度 iframe 和升级面板上下堆叠。

产品页继续只保留黄色用户操作提醒；身份／指纹、供电／温度、录制／自检阻断、UNKNOWN 状态阻断、账号隔离及售后日志规则不变。

## 验证范围

- 修复前，元数据检查不下载完整包的回归失败；修复后通过。
- OTA Rust 回归 6 项通过：四资源元数据检查、延迟制品下载与固定 URL／摘要拒绝、账号隔离、网关有界重试、404 不重试、响应体超时与取消等。
- 设备与服务界面回归 20 项通过：源站失败说明、设备保持连接、旧预览清除、重试成功、两面板切换、未提交输入保留、原生导航及无配置／安装请求等。
- 设备布局在 1920、1440、960 和 390 px 宽度验证；源站错误在 1440、960 和 390 px 验证。
- `pnpm check:full` 通过，包含前端 production build、Rust format／Clippy、常规测试及 Tauri debug no-bundle 构建；Rust 主测试集 359 项通过、17 项按既有环境条件忽略。Wiki 链接检查及差异空白检查通过，正式三平台产物状态以对应 CI／Release 为准。

真实设备 HTML、网络证据、截图和测试日志保留在私有诊断目录，不进入仓库。本轮未执行设备安装、现场语音、生产诊断 POST、代领代审、配置写入或业务服务重启。源站恢复、真实下载与实体安装健康窗口不能用隔离回归替代。
