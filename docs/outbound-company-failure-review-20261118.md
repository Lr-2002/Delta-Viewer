# 星矩公司范围与故障视频审核（1.12.1）

用户确认外发审核只接收交付平台“星矩”公司的数据。平台以经运维核对的公司主记录 ID 配置审核范围，使用数据上传时冻结的 `customerId` 判断归属；批次名称不是公司依据。列表、领取、结论和媒体读取使用同一范围，保留其他公司的原记录与审核历史，不自动移公司或代审。

用户同时明确，视频缺失、损坏或无法加载不能使审核员无法记录问题。客户端保留“有效数据”须全部视频就绪的门禁；已确认缺失相机／分段、无视频或读取失败时，可以打开独立异常／无效窗口，填写原因提交。普通连接尚未完成且没有失败证据时不提前放行。

无效原因增加“数据缺失”“视频损坏”；异常原因增加“部分数据缺失”“部分视频损坏”，自定义原因仍按类别分别保存。结果由审核员主动选择，客户端不因超时或损坏自动判断；首次结论保存后自动下一条，修改既有结论留当前条目，未改变原因不重复保存。提交回执不明只读核对，权限、领取、版本冲突与忙碌门禁继续保持。

平台保留已提交且来源绑定完整的清单录制，即使某一录制没有 MP4，也能记录缺失结论；无视频录制不得判为有效。源清单签名、上传回执、源文件、派生描述与历史记录保护不变。

浏览器回归使用真实 H.264 和实际失败请求，覆盖七路全部失败时提交视频损坏并自动下一条、缺一路时修改异常原因并更新独立统计、零视频时固定七路显示缺失并提交数据缺失。服务端隔离验证覆盖不同公司名称相似、星矩批次不含关键词、指定其他公司 ID、领取及媒体越界拒绝、无视频录制结论，以及原有并发、取消与原因分库。

本版本另开 Windows 预览并完成完整门禁。平台协议启用、真实窗口验证与正式 Release 以实际检查结果记录；不把隔离测试视为生产审核，也不代用户提交生产结论。
