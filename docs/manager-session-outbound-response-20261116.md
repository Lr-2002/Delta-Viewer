# 登录保持与外发响应核对（1.10.5）

日期：2026-11-16。包含未发布的 1.10.4 完整候选 `f49d64964e9b40872ac71c753cdac92e7f9b365e`；正式基线为 1.10.3。

## 登录丢失

原生 `get_auth_status` 调用 `workspace_mode::restore`，后者即使读取到相同工作模式也调用清除当前用户／令牌的 setter。复现测试先恢复模式、登录，再重复恢复即得到 AUTH_REQUIRED；改为锁内比较模式，相同模式保留已有进程内会话。显式选择模式、退出、实际模式变化仍清除权限；读取不会恢复已退出令牌。没有新增密码或令牌落盘。

此次排查也调用过旧正式包的状态接口并触发清除，已告知用户；不能将由诊断触发的现象视为所有历史“空闲掉线”的完整证明。旧窗口 UI 可能保留用户名称但原生会话已空，窗口中尚未持久化事件必须保留，不能关闭、重载或用磁盘快照覆盖活动队列。

只读核对当前运行用户中心：1.8.6-outbound-20261111，11 月 11 日启动，持久会话 SQLite 存在；运行源码默认 30 天滑动期限。配置未设置 sessionIdleTtlSeconds，旧 sessionTtlSeconds=28800 不改变滑动机制。已有 15 秒真实在线上报续期，不需要增加虚假活动或部署／延长服务配置。隔离回归验证 9 小时空闲、休眠断网两天、重启、原事件重传去重，主动退出、暂停和密码变化仍撤销登录。未进行生产账号写入。

## 整页按钮同时等待

原组件仍使用共享 busy/busyRef；先前仅将转圈图标放在当前行，其他行的 disabled 条件没有解除，原回归甚至要求其他行禁用。红回归证实，先前交付对此解决不足。

新实现以批次 ID 独立互斥、忙碌和结果提示；不同批次可并发，同批双击只发一次。写回执不明确时只读核对，不重放。后台列表请求失效后不能覆盖已完成操作。较新的打开意图优先，父页面在草稿保存／审计等待后再次核对意图；换账号、离页后迟到响应不能跳转或恢复旧权限。

会话中仅记住平台明确返回 OUTBOUND_REQUEST_INVALID 的能力拒绝，随后直接使用兼容列表或回执。超时不等于旧协议，不能触发重发写操作；不缓存账号令牌、业务权限或批次响应。账号和视图重建时能力记录重新创建。

## 视频和列表仍受服务端影响

本轮只读现网样本：

| 请求 | 耗时／结果 |
| --- | --- |
| 摘要列表 | 928ms，旧平台拒绝字段 |
| 兼容完整列表 | 622ms，14 批／198 条，643718 字节 |
| 单批详情 | 1027ms，旧平台拒绝字段 |

这些是当次样本。历史相同服务曾有 11.8–12.3 秒列表等待；媒体首响应等待 5.2–8.7 秒，正文约 0.24 秒。不能把当前 622ms 当作固定性能，也不能把历史 12 秒描述成当前恒定耗时。当前新媒体探测未获得已领取批次，没有进行真实领取，未伪造新的成功播放计时。

只读部署源码仍为旧协议：每次列表同步修复已审 description；媒体票据和每次 Range 反复刷新无关就绪状态、投影整批录制，Range 打开再次投影。MP4 尾部索引会放大重复 Range 等待。现网没有优化版 Server-Timing。交付平台 PR #128 实现摘要／单批／紧凑响应、目标录制投影和后台描述修复，以及启动后新完成上传同步，但仍 OPEN、未上线；Manager 修复不能替代该部分部署验收。

平台协作要求由 zhaowuc 验收合并，代理不自行合并自己的 PR；CI 受账号额度阻断，平台完整测试另有 clean main 可复现的 admin-service 基线失败。不得声称平台全量通过或生产视频速度已解决，不部署／重启服务。
