# 1.2.0 目录迁移与人工结果精简

日期：2026-10-21。基线：1.1.9，c641dab。

## 已确认原因

NAS 根目录增加 `D1 daily`、`D1 validation`、`D1 yiqi` 分组后，旧客户端、旧索引的领取标识都使用数据集相对路径第一层。因此同组的不同日期批次共用一个领取键，点击一个批次会展示整个分组已领取。索引回包和客户端逻辑均已核对，此问题是软件层级假设，不是审核员重复领取。

旧单条导航也把第一层当批次，源扫描仅查一层；旧目录恢复、草稿、待写队列和预览继续指向迁移前位置。另有三个记录跨批次迁移并改名，恢复位置必须由当前记录推导实际批次，不能只迁移旧批次路径。

针对“文字保存但结论、新增/删除片段未保存”：元数据副本上的通过、不通过及结构编辑原流程可以成功重载，未复现所有审核员个例。已确认一个兼容缺陷：选中人工 `desorption.json` 时仍固定写 `description.json`，查看旧文件会看不到新结论及片段。本版按选中人工结果名称保存，根级 `session.json.qc` 必须同时写入后才确认完成。现场数据卷核对时已有约 1.26 TiB 可用空间，本次不能继续归因于上一版满盘问题。

## 修复范围

- 分组不可领取，真实日期批次独立领取；递归查询、释放、未审核过滤及进入审核使用真实批次。
- 保留服务端索引原字节哈希、节点范围和刷新回执校验，校验成功后才适配旧索引的批次身份。不在客户端重新扫描全部媒体。
- 仅用已确认 completed 迁移恢复不存在的旧路径；最长前缀、边界和链接校验，不按同名编号猜测。已存在旧路径保持原样。直接源扫描增加 32 层、100000 目录上限，发现 session 后停止深入。
- 本机待写队列只使用本机迁移缓存；补写保留原事件 ID、发生时间、初始基线和账号隔离，真实冲突仍保留本机结果。恢复登录时由迁移后的记录确定批次，兼容个别记录跨批次改名。
- 自动预览在新位置尚无预览时按明确映射寻找旧预览，仍核对清单、原片大小/时间、头尾样本和时长。此修复不生成新预览，也不宣称所有数据已有预览。
- 选择人工 JSON 作为来源时，下一次保存及离线补写以当前人工文件哈希为基线，避免把自身上次保存误判为来源变化；保留真实共享修改的哈希门禁。
- 人工结果 `_human_review` 只保留 `status`、`reviewer`、`reviewedAt`；pending 的署名、日期为空，approved/rejected 对应通过/不通过。保留原有片段格式和未知数据字段，新增/删除实际更新数组。
- 完整修订、改动摘要及恢复状态另存 `.description.review-state.json` / `.desorption.review-state.json`，绑定人工结果字节哈希及输出名。技术文件先原子写入，失败不发布人工结果或确认成功；人工写入后中断仍可从 pending 草稿恢复。
- 兼容旧完整 `_human_review`，加载不改写；仅下次明确保存才转换。勘误及撤销技术标记另存，本机完整撤销历史继续保留。统计从真实片段数组计算，兼容旧元数据格式、零/一基帧和开/闭区间；同时存在两种人工文件名时优先匹配当前 QC 审核人及日期。
