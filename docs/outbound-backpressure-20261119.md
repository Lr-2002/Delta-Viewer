# 外发媒体缓冲暂停与传输截断（2026-11-19）

1.12.2修复客户端原生视频代理的慢消费者故障。浏览器因缓冲、暂停或解码暂不接收本机HTTP正文时，旧实现阻塞在socket写入，`buffered(4)`内尚未完成的上游分块Future也停止轮询。reqwest请求截止仍计时；恢复消费后，健康源读取被判超时，截断已声明长度的响应，出现视频传输中断或读取超时。

每个已发出分块改为独立Tokio任务，避免本机socket背压阻塞上游正文读取；任务句柄随请求释放时abort。16MiB响应窗、四路1MiB分块上限、25秒请求与15秒读截止、逐Range领取和源对象校验保持。首块发送后及时释放，不新增媒体缓存或原始文件写入，也不降低画质。真实源慢或解码能力不足仍可能等待，此修复不能保证所有电脑七路8倍流畅。

## 证据

- 回归`paused_browser_body_does_not_expire_healthy_upstream_reads`：快速源请求截止1秒，本机接收暂停1.5秒后恢复，16MiB响应逐字节一致，路由无故障。
- Linux `cargo test --manifest-path src-tauri/Cargo.toml --lib outbound_media::tests -- --nocapture`：6项通过，含七路范围完整性、注销／断连取消及索引检查。
- 独立诊断程序在同一Windows及真实源文件暂停接收32秒：旧实现仅收到5,242,880字节，`UND_ERR_RES_CONTENT_LENGTH_MISMATCH`；新实现收到16,777,216字节，错误为空。诊断程序只替换运行时／权限外壳，不是新版Manager，不能称正式交付已完成。
- 正常网络下，原实现七路首段及后台时长读取也可约3.7秒就绪；故障由暂停消费条件触发，并非每次打开必现。

原始只读证据在仓库外`diagnostics/outbound-isolation-20261117/native-transport-probe-20261119/`，不提交私有画面、媒体票据或二进制。
