# 1.10.3 首页连接与外发恢复验证

2026-11-16，基于正式 1.10.2。保留三模式 SSH、售后诊断、升级日志、黄色操作提醒、快速加载、常用标签和已有审核资料。本轮不执行实体设备安装、现场语音、生产诊断 POST、真实领取／结论、服务部署／重启，不关闭已有 Windows 应用或覆盖活动队列。

## 首页

每种连接方式固定显示设备管理、设备信息、检测排障三个入口。IP／AP 显式连接成功留在首页，Type-C 沿用自动发现；点击功能按钮才跳转。连接失败或切换模式清除旧确认结果，AP 仅配置时只开放设备管理，按钮说明信息／检测不可用。黄色指南继续在连接控件下方。

Type-C 管理页面复用所选 USB 网卡、真实同网段地址及本地地址绑定，查询前后核对目标；不扫描设备、不退回其他 LAN 网卡。已确认页面由显式入口展示，手动刷新重新读取。同页导航也能退出原生页面，返回首页无需先切换另一栏目。

## 外发断连与同步

现场 Windows 原生 outbound_review_call 只读 list 在 12,052ms 报 OUTBOUND_USER_CENTER_UNAVAILABLE；同源平台全量列表在 12,294ms 正常返回 14 批／198 条，后一次 11,824ms。实际 dohc-user-center.service 为 user service，PID 3771599，TCP 10.1.41.17:17880 可达。错误原因是客户端复用了普通身份 API 的 12 秒总时限，短于中继上游 30 秒，不能据错误文本认定用户中心停止或网络断开。

外发 HTTP 单请求改为 40 秒，普通身份 API 保留 12 秒。复核账号会话，固定路由与证书规则保持；响应最大 2MiB，超时／连接／TLS／传输与 HTTP 状态分别分类，不返回 URL 或凭据。只读 list／video-url 的连接和传输中断最多重试一次，不重试超时、HTTP 业务拒绝或写操作。写回执不明时读取当前批次核对真实领取／结论，读取失败阻断下一次提交并保留核对入口。

任务中心每次前台读取完成后 5 秒轮询，焦点恢复补读，隐藏／业务忙时跳过；请求不重叠，迟到列表不覆盖正在进行的操作，失败保留现有队列。它不是推送协议，实际可见时间仍取决于上传提交和服务响应。

交付平台 PR #128（6bcf7e3）合入最新 main d2573f5，并补充外部启动后新完成上传的补载；新回归在缺失补载时失败，修复后通过。平台仍未部署，不能声称现场首屏已提速。首响应减少重复就绪刷新、全批投影和 description 写回的原有优化继续保留。PR 由 zhaowuc 验收合并；GitHub CI 43801565201 因付款／额度限制未开始任何 step。平台全量检查的 admin-service.mjs:24 预期 3／实际 0 在干净最新 main 隔离归档复现，不冒充全量通过。

## T265 与恢复

截图对应 t265_right-00000.mp4 实际存在，152,129,393 字节与源清单一致；每侧 7 段，共 5 路／35 文件。只读取首尾各 1MiB 的稀疏探针可由 ffprobe 读出 H.264、848×800、300 秒。此证据只确认存在、大小与头尾索引，不代表全片 hash 或解码通过；截图发生时浏览器状态未保留，不能宣称已复现当时具体网络／解码错误。

前端确有独立状态问题：error 曾永久设置失败，却未移除 ready，后续 canplay 也未清除。现在按真实播放器状态逐路更新，失败不再显示就绪；只重取失败路票据，保留其余缓冲，恢复到主路时间。媒体错误区分网络／解码／不支持或响应异常，切换时 abort 不误报。真实缺段仍阻断审核，不能以下一段填洞；相机数与分段来自实际清单。
