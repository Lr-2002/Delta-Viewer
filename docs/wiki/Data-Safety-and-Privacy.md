# 数据安全与隐私

DOHC Viewer 的源数据工作流只通过操作系统已经挂载或映射为目录的文件系统路径访问数据，包括本地目录、SD 卡和网络映射盘。启动时先选择工作模式：统一管理模式才会通过固定证书连接局域网用户中心完成登录并使用自动更新；离线模式不创建账号、不请求用户中心或更新镜像：

- 不支持在应用内配置或连接 SSH、HTTP、云存储或 NAS 协议数据源；操作系统已挂载的 Windows 映射盘、SMB/NFS 目录可作为源目录。扫描、检查、回放和导出保持只读，保存标注要求目录可写。
- 统一管理模式的用户中心只处理账号登录和管理员创建账号，不接收采集数据、路径、标注或报告；登录成功后会话只保存在客户端进程内。
- 离线模式没有账号或用户中心会话，扫描、检查、回放、标注和导出仍然在本机完成；离线标注使用固定本机 provenance 标记，不在界面显示为处理人。
- 不收集遥测，不上传路径、图像、状态、账号、标注或 hash。
- JPEG、`states.jsonl`、骨架和其他采集文件只读；正常界面直接读取源路径，不在 app-local-data 自动复制 episode。保存标注是唯一写入例外，只原子更新当前 episode 根级 `description.json`；导出只写用户选择的导出目录。
- 独立 formal/development stress 仍保留完整导入、目标端大小和 BLAKE3 回读，用于验证导入器和大容量数据链路；这不是正常用户流程。
- 正式输出使用 partial 加同文件系统原子发布，不覆盖已有结果。
- 统一管理模式本地登录后才会从固定公网镜像 `http://39.155.172.162:17879` 和固定局域网镜像 `http://10.1.11.200:17879` 读取 `latest.json` 及当前平台更新资产；发现更新后以两个 32 KiB Range 样本并行测速，选择更快的可用完整下载路径。离线模式不执行更新请求。客户端不访问 GitHub，请求不附带账号、源路径、标注、报告、hash 或遥测。镜像断开或更新失败不影响核心数据工作流。

## 为什么不再自动复制

自动复制大容量 session 会额外占用接近源数据大小的磁盘空间，重复选择记录时尤其浪费。正常流程因此改为直接从已挂载源目录检查、回放和导出，不创建等量副本。扫描、检查、回放和导出不修改源；保存标注需要写入很小的 `description.json`。使用期间必须保持 SD 卡连接，拔卡、卸载或读卡器中断会使当前操作失败；源介质的随机读取速度也会直接影响回放和导出速度。

本机标注批量导出遵循同一原则。app-local 标注目录保存任务、描述、轨迹码、统一管理处理人或离线本机 provenance、源路径和指纹；源 episode 另保存 `description.json`。批量操作不会提前复制或缓存 JPEG/状态数据，而是在开始每条导出时重新读取并核对原始源。因此它不会额外占用一份源数据大小的 app-local-data 空间，但源卷必须在线且采集内容不能变化。

旧版本可能已在 `app-local-data/imports` 留下导入副本。应用不会自动删除这些历史数据，避免误删用户仍需保留的文件；确认不再需要后，用户可以在应用完全退出时按操作系统的数据位置手工归档或清理。

GitHub Release 的构建过程需要网络下载编译依赖、reviewed FFmpeg 和 WebView2。macOS 构建机只在本地生成不含身份的 ad-hoc seal。自动更新包另由发布流程使用专用 Ed25519/Minisign 私钥签名，应用以仓库中可审查的内嵌公钥验证；该签名不代表安装器具有可信发布者身份。私钥只保存在发布者受控位置和 GitHub Actions secrets，不进入仓库或 artifact。

应用只允许 updater 模块访问固定的 `http://39.155.172.162:17879` 或 `http://10.1.11.200:17879` origin 及清单指定的精确版本目录。镜像只会按受信任的请求 Host 重写为这两个 origin 之一，任意其他 Host 始终得到公网地址。测速仅接受固定 32 KiB 的单段 `206` Range 响应和精确 `Content-Range`，且不改变完整更新包的 URL、大小或签名门禁；全部测速失败时保留清单 URL。更新包按清单精确大小有界读取，允许范围为 1-64 MiB，URL、大小或签名任一不匹配都拒绝安装并保留当前版本。HTTP 不提供传输身份保证，因此 Ed25519/Minisign 验签不可关闭；能够修改传输流量的攻击者最多阻断或隐藏更新，无法构造可安装的篡改包。

镜像机是唯一访问官方 GitHub Release 的运行时组件。它每 5 分钟同步一次，先验证三个 target、文件名、大小、SHA-256 和更新签名，再把完整版本从服务自有 partial 原子切换为当前版本；失败继续提供上一完整版本。镜像对客户端只开放 GET/HEAD，支持受控的单段文件 Range，不记录账号或业务数据，只保留当前版和上一版两个 release 集合，避免缓存无限增长。

## 文件系统

Windows 和 macOS 不能直接读取普通 ext4 SD 卡。macOS 使用第三方驱动时必须按[Paragon extFS 只读教程](Paragon-extFS-macOS)关闭 Spotlight indexing 并确认卷为只读；第三方驱动的安装、激活和网络行为不属于 DOHC Viewer。Ubuntu 可用 Linux 内核原生只读挂载 ext4；原生 deb 可访问当前用户有权限的挂载目录。exFAT 可以改善跨平台挂载，但格式化会清空现有数据，而且 exFAT 不带日志。切换前必须完成备份、hash 校验、长时写入、接近满盘、断电和重新插拔测试。

导出目标卷应使用 NTFS、APFS、exFAT 或其他支持大文件的本机文件系统。FAT32 有 4 GB 单文件限制，不作为受支持的导出目标。

## 本地数据位置

Windows 的账号、自定义任务、轨迹占号、标注、后台报告和操作错误历史位于当前用户的 Tauri app-local-data；macOS 位于 `~/Library/Application Support/com.dohc.viewer/`；Ubuntu 原生 deb 通常位于 `~/.local/share/com.dohc.viewer/`。正常界面不会在这里新增 episode 数据副本。旧版本可能仍留有 `imports` 目录；卸载应用不会默认删除这些本地数据，删除前应先确认内容并完成必要归档。
