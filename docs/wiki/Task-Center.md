# 任务中心

审核账号顶部进入“任务中心”，替代旧个人任务详情。默认打开已挂载的 Delta-D1 数据集；“更改目录”按当前账号记忆选择。目录树可逐层展开，显示批次领取人、审核进度，以及 session 的已审核/未审核/异常状态。点击 session 打开审核工作区。

进度以根级 `session.json.qc` 为准，通过与不通过都计入已审核，空值为未审核，无法识别或读取失败显示异常。百分比为已审核数除以 session 总数，按数量加权；目录读取不完整显示 `--`，不显示虚假的 100%。扫描跳过相机文件，最多八个并发元数据读取；页面可手动刷新，每轮完成后等待 60 秒再更新 QC。领取状态单独每 15 秒刷新，同一目录的扫描不重叠，后台更新时仍可展开和打开已有条目。页面隐藏时暂停发起自动刷新。

未领取的批次可以领取，已领取的批次禁止重复抢占。同一账号重试幂等，两账号同时领取只有一人成功。用户中心连接失败时保留目录和已知进度，禁用领取并显示错误。已领取不自动过期；管理员在监管账号“任务中心”释放或转交，服务保留变更历史。转交目标必须为启用的审核账号。

需同步部署 `scripts/user-center-server.mjs`、`scripts/review-audit-store.mjs` 和 `scripts/task-claims-store.mjs`，保留原账号、证书、service ID 和数据目录。领取记录保存在服务端 `task-claims.sqlite`，不能用客户端本地状态替代。普通用户中心请求只包含批次哈希标识和账号，不发送完整源路径及 QC 文件。

Delta-D1 下相同批次通过不同挂载盘符访问时共享领取归属，选择其子目录也保留批次身份。其他数据集以根目录名称作为命名空间，管理员应保持数据集名称唯一，避免不同数据集使用同名根目录和同名批次。
