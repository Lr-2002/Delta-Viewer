# 回放与裁剪

正式版 `1.0.2` 校对页采用主视频、播放条、起止边界预览、人工复核与右侧动作列表布局。分段条或列表可定位片段，播放按钮播放该段；结束帧按不包含显示，超出视频末尾的边界预览显示最后实际帧并标明。查看 JSON 显示原机标内容。

回放页使用统一时间轴显示五路相机画面，并同步位置、速度、欧拉角和角速度曲线。X/Y/Z/W 使用稳定的红、绿、蓝、紫，并辅以不同线型和文字图例；播放、暂停、前后步进、时间轴和 `0.25x / 0.5x / 1x / 2x` 速度均作用于同一时间轴。

MP4 连续播放以 Camera 0 实际呈现的画面驱动时间轴和骨架，其余画面按原生帧率跟随；15 FPS 的源视频不会变成每秒 30 个不同画面。主视频开始或网络欠载时先等待短时内存缓冲，其余原生画面随之暂停，缓冲充足后恢复。暂停和定位时，各画面重新对齐所选位置。播放、倍速和骨架更新不会反复跳转主视频。

NAS 视频通过仅绑定本机的只读媒体服务加载，按请求范围分块读取，不创建本地视频副本。NAS 持续吞吐低于视频总码率、其他程序占用网络或源目录被移动时仍可能卡顿或无法读取。

连续播放先为 Camera 0 建立有界预读跑道，再由主时间轴按记录速度推进；四路次要画面在播放期间以约 10 FPS 跟随，暂停或定位后恢复所选精确帧。对于逐帧 JPEG，SD 卡和本地盘保留较长的 Camera 0 跑道；SMB/NFS 和 Linux 文件管理器挂载的 GVFS 网络源只等待 30 帧，并为四路小画面按实际显示步长各自预读 12 帧。这样从中间定位时不必先读取数百个远程文件，小画面也不会因为 NAS 单文件往返延迟长期停住。

所有 JPEG 预读只存在于当前进程的有界内存中，不写本地代理、不复制或修改 NAS 数据。普通 JPEG 目录由后端使用进程随机 token 注册到仅绑定 `127.0.0.1` 的只读帧地址，WebView 直接取得并解码，不再把每张图片转成 Base64 后通过 IPC 搬运；地址不暴露源路径，只接受十进制帧号并拒绝符号链接文件。网络吞吐低于五路预览需求时仍可能短暂显示较早的已解码小画面，但新的定位会废弃旧排队任务并从所选帧重新开始。

主画面当前帧无法读取时会停止加载并显示错误。次要画面暂时读取失败时可保留最近成功解码的预览，不阻塞主画面；这类预览不代表当前帧已完成精确解码。点击带帧号的数据检查 issue 可以跳转到对应位置。

## 对照机标结果

加载数据后点击“校对”，读取该数据根目录中的 `bailian_annotation.json`，展示 Camera 0、动作描述、视频帧范围、模型与校验状态。视频帧号独立于状态时间轴和人工裁剪。拖动、切段、边界预览使用同一视频帧号，连续片段无缝连接，真实缺口以斜纹和“未标注”帧范围显示。

正式版 `1.0.2` 使用正式配置/标注目录和更新通道。历史开发版的独立本机配置和人工标注目录不会自动合并；已批准的源目录复核 JSON 可以在正式版重新加载。

选择片段后可修改描述、输入或拖动起止帧、删除或恢复片段，并逐段点击“合格/不合格”。共享分界同时移动相邻片段边界，保留每段至少一帧。修改实时保存为本机草稿；所有保留片段合格后，才首次生成数据根目录中的 `bailian_annotation_reviewed.json`。其中保留原 JSON 未修改字段，合并人工修改和删除，并记录独立人工判定。生成后继续修改会实时更新该文件并撤销对应片段合格状态。保存错误会保留待保存内容，支持重试；原机标或其他电脑修改产生冲突时拒绝覆盖。

源 `bailian_annotation.json` 始终只读。校对不会写入 `description.json`、创建原人工标注修订或让目录显示“已标注”。点击“回放”返回原人工标注范围。

当前支持 `schema_version: 3` 的 `episode_results[].annotations`，按与数据目录名称一致的 `episode_id` 选取结果。机标视频帧从 Camera 0 映射到 Viewer 主时间轴；`[start,end)` 转为包含末帧的显示范围，支持显式 0/1 起始帧及闭区间。旧文件未声明规则时暂按 0 起始、左闭右开解释，并显示待核对提示。帧数与 Camera 0 不一致、无法可靠对齐时仍展示文本但禁用跳转和播放，不拉伸或猜测时间轴。文件不存在、格式错误或超出 8 MiB/2000 片段限制时单独提示，视频和人工标注仍可继续。

## 创建人工片段

载入 episode 后，片段时间线默认以完整轨迹显示“片段 1”。把播放头移动到需要的边界并点击“在当前帧分割”，当前片段会分成左右两个连续片段：左侧包含当前帧，右侧从下一帧开始。重复操作可以继续细分所在片段；合并删除片段会把它并回相邻片段，因此整条轨迹始终连续且没有未覆盖帧。

## 选择轨迹范围

轨迹范围是一个连续的闭区间，起点和终点都包含在导出中。可以使用双范围滑块、数字输入，或把当前帧设为起点/终点。重置后恢复完整轨迹。

保存片段后，再次进入同一 episode 会先显示只读画面预览，检查和标注恢复完成后再显示时间线编辑器，恢复已保存的起止帧和片段，播放从保留范围起点开始。旧的完整轨迹草稿不会覆盖已保存的截取范围。仅保存任务、尚未正式保存片段时，仍可恢复本机片段草稿。

裁剪只改变当前回放与本次导出：

- 不修改源 SD 卡。
- 不创建或修改本地 episode 副本。
- 不重新复制或重编码范围外 JPEG。
- MCAP、HDF5 和 LeRobot 使用同一范围。

范围外、能够绑定到具体帧的 issue 不阻断本次导出；范围内 issue 和无法绑定帧的全局 issue 仍按错误/警告规则处理。
