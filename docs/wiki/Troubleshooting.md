# 故障排查

## 选择不到 SD 卡

先确认操作系统文件管理器能够看到卷和 episode 文件。DOHC Viewer 不包含 ext4 驱动；ext4 卡在标准 Windows/macOS 上不能直接选择。macOS 用户可按[Paragon extFS 只读教程](Paragon-extFS-macOS)挂载，必须确认 `Mount in Read-only mode` 和只读卷状态。Ubuntu 原生 deb 可选择当前用户有权读取的只读挂载目录。不要为了读取数据直接格式化仍含数据的卡。

## 选择目录后没有继续

扫描完成后不会打开本地目标目录选择框。首条记录会直接从只读源路径加载；其他记录可双击，或聚焦后按 Enter/空格按需加载。若某条记录失败，可用相同操作重试，并在顶栏打开“操作错误历史”。检查期间应保持源卷挂载。

## 读取失败或速度较慢

正常界面不会复制完整 session，因此不需要预留等量 app-local-data 空间。读取速度取决于 SD 卡、读卡器、文件系统驱动和接口；先更换可靠读卡器或端口，并确认卷没有中途卸载。导出仍需要目标卷具备足够空间，FAT/FAT32 不适合作为大文件导出卷。

## 出现 operation not allowed / Operation not permitted

应用会把原始消息保存到操作错误历史，并归类为 `PERMISSION_DENIED`。macOS 先确认 Finder 能打开该卷，再在“系统设置 -> 隐私与安全性 -> 文件与文件夹”允许 DOHC Viewer 访问可移动宗卷；Windows 和 Ubuntu 用户确认当前账号能读取挂载目录。源卡不需要写权限，不要通过 `chmod`、关闭系统保护或把源卡改成可写来绕过问题。

旧版本自动导入留下的 `app-local-data/imports` 不会被当前版本自动删除。退出应用并确认不再需要后再手工归档或清理，避免误删仍在使用的数据。

## 自动更新失败

`0.17.8` 及更早版本没有自动更新能力，应先从 [固定镜像](http://39.155.172.162:17879/) 手动安装 `0.17.12`。引导版显示检查或下载失败时，可以继续离线使用检查、回放、标注和导出；先确认客户端能打开 `http://39.155.172.162:17879/healthz`，再点击顶栏更新按钮重试。内网设备若不能回环访问公网 IP，应用会自动改用 `http://10.1.11.36:17879/healthz`；手动排查时也可打开该地址。Ubuntu 安装阶段可能需要在系统对话框确认管理员权限。

不要从第三方地址手动替换 updater 或 `.sig`。应用只接受固定镜像同 origin、精确版本目录、1-64 MiB 且通过内嵌 Ed25519/Minisign 公钥验证的当前平台资产；URL、大小或签名不匹配会按设计拒绝安装。`healthz` 显示 `degraded` 表示 GitHub 上游同步失败但上一版本仍可下载，`unavailable` 表示尚无完整缓存。持续失败时记录应用版本、平台、镜像健康状态和界面中的 `UPDATE_*` 错误码，不要附账号、源路径或采集数据。

## 数据检查出现警告

警告不等于文件损坏。常见原因包括缺帧、图像/状态数量不同、状态帧号跳变或时间间隔超过基准中位数三倍。先在回放中定位相关帧，再决定是否确认并导出。

## 批量列表显示“源断开”或指纹变化

本地标注只保存原始路径和数据指纹，不复制 episode 数据。重新连接同一张源卡，并确认操作系统把它挂载到标注时的相同路径；应用不会自动把旧标注改绑到另一个目录。如果路径已被其他内容占用，或源文件发生变化，该条批量导出会失败，以免把轨迹码附到错误数据上。其他有效条目仍会继续。

## Foxglove 打开 MCAP 显示 Permission denied

macOS 可能使 Foxglove 保存的最近文件权限句柄失效。不要修改 MCAP；在 Foxglove 中使用 **Open local file(s)** 重新选择该文件。

## LeRobot 提示找不到 FFmpeg

镜像中的正式安装包已内置并校验 FFmpeg。出现该错误时先确认安装来自固定镜像且 hash 匹配；不要把本地 debug app 当作发布包。问题报告中附上应用版本、平台、导出错误摘要和安装文件 hash，不要附原始图像或账号密码。

## 忘记本地账号密码

当前没有远程找回。账号只存在本机，维护人员应在保留标注审计记录的前提下处理应用 local-data；不要直接编辑账号 JSON 或替换密码哈希。

## macOS 提示应用已损坏或无法验证

`0.15.0` 的 macOS DMG 存在无效 app 资源封印，会触发“已损坏”，不能通过安全设置绕过。请删除该 DMG 和 app，安装 `0.15.2` 或更高版本；`0.15.1` 没有公开 Release，Windows `0.15.0` 不受影响。

`0.15.2` 及更高版本没有 Developer ID 或 Apple notarization，因此首次启动出现“Apple 无法验证”或“无法确认开发者”属于预期策略阻止。先确认下载自本仓库、芯片架构正确并核对 `SHA256SUMS.txt`，再按[安装与升级](Installation)使用“系统设置 -> 隐私与安全性 -> 仍要打开”完成一次性授权。不要关闭 Gatekeeper，也不要运行移除 quarantine 的命令。

若 `0.15.2` 或更高版本仍显示“已损坏”，不要绕过。hash 不符时删除文件并重新下载；hash 相同时在 GitHub Issue 中附上版本、macOS 版本、芯片架构和 DMG hash，不要附原始采集数据或密码。
