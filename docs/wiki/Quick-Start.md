# 快速开始

## 1. 选择工作模式

首次启动先选择工作模式：

- **统一管理模式**：导入管理员提供的用户中心配置，再使用管理员创建的账号登录。账号只用于记录“这条数据由谁处理”；账号创建和密码重置由用户中心管理员完成。服务部署步骤见[用户中心部署](User-Center-Deployment)。
- **登录模式**：所有用户导入管理员配置并登录后才能扫描、检查、回放、标注和导出；离线身份模式已停用。

切换工作模式会清空当前载入的 episode、检查和标注状态；统一管理模式切换后需要重新登录。

## 2. 选择 SD 卡

点击顶部的“选择 SD 卡”，选择操作系统已经挂载的卡根目录、本地测试目录或网络映射盘目录。应用会立即扫描直接子目录中的全部 session，并直接从源路径加载第一条记录。不会出现本地目标目录选择框，也不会自动复制 session。

也可以直接选择包含 `segment-000000.bin`、`segment-000001.bin` 等文件的目录。文件数量不固定，应用按文件名中的编号做数值排序并把全部 segment 连续视为同一条 T265 数据；无关文件会忽略，编号缺口会作为明确警告显示。该格式当前支持只读扫描、检查和回放，三种导出格式尚未适配并会由后端明确拒绝。

真实采集盘可以直接选择 `/media/descfly/DOHC1TB` 这类批量根目录，也可以选择单个日期开头的记录目录。对于 `hybrid-h264-jpeg-segment-v1`，应用会把日期目录顶层的相机 MP4 与 `t265/segments` 内的左右目 JPEG、pose 合并成同一条数据，按首个 T265 batch ID 对齐时间轴；不需要再手动进入最内层 `segments`。只有 `.partial` 或零长度媒体的中断记录会保留在列表中并给出数据错误，不会导致桌面端崩溃。

初始扫描只识别 session，不遍历每条记录的图像树，也不读取每个图像的大小和修改时间。左侧先显示“待读取”；激活记录后只读取状态和五路帧文件名，画面与标注区进入“快速预览”，完整文件/容量统计和数据检查随后继续。检查完成前不能导出。索引只在当前进程内短暂缓存，源卷在预览、检查和导出期间都必须保持挂载。

扫描、检查、回放和导出不会修改源采集文件。保存标注时会在当前 episode 根目录创建或更新唯一的 `description.json`，因此标注用源卷需要具备写权限；严格只读挂载仍可检查、回放和导出，但不能保存标注。应用不会修改或删除 JPEG、`states.jsonl`、骨架及其他采集文件。操作期间必须保持源卷挂载并连接稳定。

## 3. 等待读取和检查

首条 session 会自动进行结构与状态全量检查，并在实际存在的图像流固定百分位执行 JPEG 解码抽检。segment BIN 还会检查记录头尾、长度、pose JSON，并在抽检或回放读取时验证 payload 与整条记录 CRC32。进度条会显示阶段、当前路径、文件进度以及耗时。正常界面不调用导入器，也不会在 app-local-data 中生成一份源数据副本。

交互抽检不等于全量 JPEG 验证；具体覆盖范围见[数据检查](Data-Validation)。源卡拔出或挂载中断后，当前数据将无法继续回放或导出，重新挂载后再选择目录即可。

## 4. 选择其他 session

左侧列表只用于选择 session。单击更新选中项；双击，或聚焦后按 Enter/空格，才进入正常回放：

- 已经加载的 session 直接进入回放。
- “待读取”的 session 激活后先进入“快速预览”，完整检查结束后显示精确状态数和容量；读取失败的 session 可再次双击或按 Enter/空格重试，错误会保存在顶栏的操作错误历史。

## 5. 检查、标注与导出

先查看[数据检查](Data-Validation)结果，再到回放页确认五路画面和彩色状态曲线。可以选择已有任务，或只输入任务名称创建新任务；任务描述可编辑，轨迹码只读并在保存时由系统自动编号。保存成功提示 `description.json 已更新`，并在当前 episode 根目录生成可直接查看的描述 metadata。之后可在导出页选择 MCAP、HDF5 或 LeRobot v2.1。

需要处理多条已标注数据时，打开“批量”页，勾选源仍可用的轨迹，选择一种格式和一个目标目录。应用会顺序重新检查并完整导出每条 episode；单条失败不会中断后续条目。标注不包含数据副本，因此原始源卷必须保持挂载且内容不能变化。
