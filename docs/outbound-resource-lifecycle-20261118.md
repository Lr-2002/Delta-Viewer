# 外发连续切换资源与异常审核（1.11.5 候选）

用户报告其他 Windows 电脑打开外发审核或切录制时卡顿、整页无响应，现有目标机流畅。受影响机器配置、WebView2 版本和故障日志尚缺，不能断言已定位所有用户卡死的唯一原因。

回归保存旧视频引用后切换录制，1.11.4 中旧元素保留 src、未回到 NETWORK_EMPTY；原测试确定失败。候选在媒体元素真实卸载时主动暂停、移除 src 并 load，浏览器取消网络和释放解码状态；布局、中英切换和批次计数刷新不卸载当前视频。原生 release-media 只处理本进程固定回环地址和当前账号会话的随机媒体路由，标记释放也使已开始的读取失效，不调用远端接口或删除源文件。

票据调度在整个工作区内共享四个正在执行的 IPC 请求。快速切换替换旧队列，已发出的旧请求不重放；迟到成功票据立即释放。切换、离开及换账号取消后续工作。媒体仍七路完整展示、原样解码，严格来源／Range／ETag、大小和会话校验保持。

用户指定异常数据为第三类，协议值 anomalous；有效、无效、异常分别计数，已审是三者之和，合格率仍是整条有效数除总数。异常表示有效与无效内容混合，不假定精确百分比。异常／无效共用内置和持久化自定义原因，提交值保留中文原文；回执不明只读核对 value、actor、reason，一致才进入下一条。旧服务未在 decisionValues 中声明支持时不发送异常写入。

验证：原资源回归失败，修复后通过；6 倍 CPU 限速下 24 次实际点击切换，144 个旧播放器全部清空，只保留当前七路；调度合成 100 次切换验证最多四个请求在途、旧排队不发出。真实 Windows 与完整门禁结果另行记录，生产结论由用户判断，合成提交不等于生产代审。

另修复旧录制未完成的 play Promise 可阻止下一录制启动：启动状态绑定当前播放代次，旧 Promise 不阻塞新代次，也不清除新代次状态。独立回归以永不结束的旧 play Promise 验证新录制仍可启动。

Windows 最终候选源码归档 SHA-256 为 `7d2041430d86d632b264b7f61170eaa70f4e0c8ec2b1f1b13541d80a01afc9c4`，二进制为 `e443fccda2ae025ab2816c1a0cb5be291eaeecb2f997da975530a62f6ff50835`；原生构建与媒体三项测试通过，已在独立窗口打开并由用户登录。依次切换八次，七路就绪约 1.2–2.2 秒，无媒体错误或丢帧；快速点击十二次约 2.34 秒，最终就绪约 3.94 秒，84 个离开的视频全部清空源，当前七路播放正常。89 秒录制观察 37.34 秒推进约 36.95 秒，未宣称观察完整片尾。所有生产验证均只读，不提交真实审核。完整本机门禁与最终外发七项回归通过。平台异常能力及用户验收仍单独核对。
