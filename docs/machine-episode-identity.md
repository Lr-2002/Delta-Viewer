# 目录移动后的机标读取（1.1.3）

目录名称是整理数据时可改变的显示名称，不应成为机标能否读取的唯一条件。按用户最新要求，1.1.3 放宽了 1.1.2 的限制：即使旧编号、路径、来源元数据指纹与当前目录不同，同目录机标仍可兼容读取。原始 JSON、编号、来源哈希和未知字段保留，加载过程不改写源机标、人工结果或 QC。

## 结果选择

优先使用与目录名精确匹配的结果，其次使用 `asset_id` 唯一指定的主结果，再次使用文件中唯一的结果。缺少 `asset_id` 的旧单结果文件也能读取；不会按编号偏移猜测。原始人工结果同样按此规则兼容目录变化，原始 JSON/reference 的无目录解析仍使用明确的原编号。

多结果可能表示不同动作周期，不能把共同帧数或指纹当作选择依据。没有唯一主结果、重复精确编号或空结果时显示具体原因，可选择其他机标来源或人工标注；不默默套用数组第一条。

自动来源优先 Flash 和原机标；不存在或不可解析时继续尝试当前目录及 `.session_meta` 中其他可识别的百炼/人工 JSON（最多 64 个候选）。手动指定来源时显示该来源自己的错误，不悄悄替换选择。

## 核验与兼容状态

- **来源核验通过**：当前主相机帧数与机标相同，平铺固定命名 cam0 MP4 的生产端 `auto_item_fingerprint` v3 文件元数据指纹也一致。
- **兼容读取、来源尚未核实**：已唯一选择当前目录中的机标，但旧指纹缺失、格式不支持、指纹不同或帧数不符。仍可查看片段；所有片段都在实际视频范围内时使用实际帧数并提示，可继续编辑审核，人工输出记录适配后的帧数；原始片段边界不缩放、不截断。片段确实超出当前视频时保留具体对齐错误。审核员需回放核对视频与动作。

指纹由相对文件名、大小和纳秒修改时间组成，是元数据指纹，不是视频内容哈希。移动、复制或文件变化均可能影响它；无法核验时不再拒绝整份机标，也不虚称来源已确认。核验只枚举当前 cam0，最多 4096 个条目，不扫描整个 NAS，不读取视频像素。链接及不支持的文件不会被跟随做来源核验。

## 旧人工记录和应急草稿

旧记录可能保留重复索引、不兼容状态或不适用于当前帧数的范围。加载时先把原始记录保存在本机应用目录的 `machine-review-recovery`，原字节按哈希去重、回读验证和原子不覆盖发布，再修复技术索引和状态；动作描述与合法边界保持。旧范围确实非法时，保留完整恢复备份，重新载入机标供继续审核，不偷偷缩放或截断人工时间范围。界面持续说明恢复内容及备份位置，恢复不视为审核通过。

浏览器应急草稿使用当前账号自己的 `:preserved:` 备份键保存原快照，恢复失败保留原记录。没有保存动作时不更新共享目录中的人工结果、原机标或 QC。正常人工保存后仍走原有修订、冲突、原子写入和操作记录落盘流程。

旧人工结果或本机草稿的 JSON 本身无法解析时，同样先备份原字节，再回到可读机标，显示持续恢复提示；无法读取或备份的 I/O 错误仍明确返回，不能伪称恢复成功。

提交的非法新片段仍不能保存；错误具体指出第几个片段、重复索引、实际帧范围、允许范围或非法状态，不再只显示笼统报错。

## 验证与边界

回归覆盖目录移动改名、缺少/变化的指纹、唯一旧结果、多主结果歧义、人工保存后重开、旧重复索引/状态、旧越界草稿原字节备份及正常源端只读。桌面和窄屏分别验证已核验/兼容读取提示、编辑及应急草稿恢复。

JSON 损坏、未知结构、非法原始片段仍需具体说明；不会伪造缺失动作或把损坏记录宣称为正常。目标 NAS/Windows 现场结果只按实际运行情况报告，不用隔离测试代替现场验收。
