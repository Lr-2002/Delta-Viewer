# D1 Manager 1.9.7 验证记录

日期：2026-11-12。基于正式 1.9.6 的状态读取补修，保留常用特殊标签及此前全部修改。

## 原因与修复

真实 D1 的 `/status` 在相机故障或低电压时返回 HTTP 503 和有效的 `dohc.device.status-summary.v2` JSON。1.9.6 的初始页面 GET 只接受 200，Manager 周期刷新也只接受 200，导致有效异常报告被当成读取失败。

原生初始读取现在仅对 `/status` 接受符合 schema 的 503；其他路径的 503、HTML 错误正文及未知 schema 继续拒绝。周期刷新接受 200/503 并核对 schema，仍按报告中的健康、告警和时效字段展示，不能将异常变成正常或将真正断连变成硬件故障。

## 回归证据

修复前：原生 HTTP 回归拒绝有效 503；实际设备 HTML 浏览器回归在刷新异常状态时未出现黄色告警，断言失败。修复后：原生传输回归通过；浏览器在桌面、最小窗口和窄窗口均能刷新异常状态，并覆盖未知 503、过期心跳恢复为无法判断。

完整发布门禁、正式三平台资产和目标 Windows 实测分别在执行后以私有证据记录，不能用本地回归代替。保留 1.9.6 的 OTA/诊断测试边界：本轮不执行实体设备安装或生产诊断 POST，未取得当前设备完整 CID，不伪造关联或借用其他设备样例。

本地完整门禁已通过：版本一致性、TypeScript/Vite、Rust Clippy、Rust 单元回归及 Tauri debug 构建；设备浏览器 18/18 通过，Wiki 16 页链接和 diff 空白检查通过。正式发布与 Windows 结果仍以交付证据为准。
