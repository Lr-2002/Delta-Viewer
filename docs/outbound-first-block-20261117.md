# 外发分块首块屏障修复候选（1.11.2）

1.11.1 已完成完整门禁、Windows 原生构建和定向媒体测试，并在 Windows 实测三条已领取录制。列表约 253–331ms，七路就绪约 2.3–5.5 秒；29 秒长片正常播完，但另一条约 9.7 秒短片仍耗约 15 秒，存在持续补充缓冲不足，不能宣称全部解决或据此发布。

每个 4MiB 窗口原先先完成第一块 1MiB，再并行后续三块，存在两阶段串行等待。新候选仅复用已核对的源站总长及 ETag，让后续窗口的四块同时请求，按顺序传给播放器。首次未知总长仍以真实响应为准；每块重新核对当前账号、平台领取、完整范围、总长、ETag（若提供）、声明及实际正文长度。对象变化时停止，不拼接不同对象。

复用的是文件元数据，不是媒体或权限缓存。仍只开放既有固定 HTTPS 来源，正常校验证书/IP，禁止重定向；随机本机路由、16 个活动本机连接、每窗最多 4MiB 堆缓冲、整体期限、退出和断连取消保持。没有修改源文件、降低清晰度、公开 BOS 地址或替代真实审核结论。

在同一短片上的临时有界并行对照约 1.1 秒七路就绪，并按正常速度播到约 9.7 秒。该结果仅为诊断原型；正式验证以 1.11.2 的编译产物为准。新增端到端测试让上游在四块请求均收到前暂不发送正文，以阻止首块串行屏障回归；既有七路顺序、异常范围、截断、源变化、断连及账号撤销测试保留。

用户验收通过前保持预览身份，不推 Manager main/tag/正式 Release，不代领、释放或提交生产审核。保留既有预览和全部修改。平台 #159 的 CI 和部署状态不变，本轮只继续客户端候选。
