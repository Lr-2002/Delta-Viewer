# D1 Manager 产品与实现契约

## 1.8.0 设备概览状态色

设备信息顶部四项概览只按设备报告及明确关联的告警映射颜色：健康状态 `OK` 为绿、`DEGRADED` 为黄、`FAILED/FAULT` 为红；报告过期、字段未知或连接读取错误为蓝色信息态。阶段故障/恢复中可显示黄/红，其他阶段保持蓝色。电压与温度没有应用自设阈值，仅在设备报告提供明确关联告警时显示黄/红。下方存储、采集写入、相机、指示灯和设备测试卡片保持中性背景，状态文字及检测排障中的完整证据仍可见。颜色不修改原始报告、检测规则或设备。

浏览器回归分别覆盖正常、降级、故障、设备关联的电压/温度告警、过期报告和分类卡片白底。相关样式位于 `src/components/manager-workspace.css`，状态映射位于 `src/components/DeviceRuntimePanel.tsx`。

## 1.7.2 原生页面与热点连接（历史）

按用户新要求，AP与局域网进入设备自己的网页，保留“返回设备管理/刷新页面”。Windows AP页读取可用Wi-Fi列表，按D1前缀推荐，用户核对标签、输入密码后以原生WLAN临时profile连接；仅匹配可见D1 WPA2PSK/AES热点。SSID不构成设备认证。密码不写普通配置/日志/报告，Rust临时内存用zeroize，前端成功/失败/切换均清空。其他平台先通过系统Wi-Fi连接，不能宣称三平台Wi-Fi已完成。

局域网输入私有IPv4后按OS路由固定GET /及/status:80，不再用健康诊断同网段限制阻挡经路由可达的地址。已实测10.1.30.114根页HTTP200，标题DOHC设备状态。AP读取实际Wi-Fi的唯一有效同网段私有网关；当前4.1，不固定188.1。不探测其他IP或猜端口、无代理/重定向、512KiB/5秒限额。

页面以只读快照嵌入opaque iframe sandbox，标签/属性白名单加CSP禁止脚本、网络、表单和子页面，不持有Tauri IPC权限；写配置/重启/配网/升级控件禁用，原页面状态手动刷新。用户尚未授权设备写操作或OTA，因此不直接执行网页JS中的status/配置/OTA轮询。AP网页可展示与健康报告可读取是不同能力，不冒充诊断成功。中文教程常显、居中、黄色提醒；旧数据区/账号/草稿/更新保持。

## 1.7.2 实际热点地址与报告能力

Windows .119实际热点为192.168.4.121/24、网关192.168.4.1，用户语音确认4.1。手册所写188.1在该电脑走USB，不能固定为AP地址。AP由Rust读取活动Wi-Fi的唯一同网段私有网关；用户点击连接才请求，前端不传任意热点host，多候选先选网卡，网关缺失/歧义时不请求；不扫描、不切网、不保存密码。Type-C仍自动发现，局域网IP仍由用户输入设备联网后的真实播报值。

固定GET /health:80实测在热点返回HTTP200、11182字节HTML，无`dohc.device.health.v1`。6f91b01提供源码`wifi_provisioning.py:599–620`对未匹配GET回退配网页面。HTML只读字节、不执行脚本，不访问页面内OTA；界面显示“地址可达·报告不可用”，不显示已连接D1、旧USB身份或硬件判断。该接口不支持健康读取时停止周期请求，支持显式重试及相同IP重试；与超时、无网卡和有效JSON分别处理。

真实AP完整诊断仍需设备侧提供正式健康JSON路由；软件修正地址与状态不能代替设备接口。未修改/部署设备服务，不猜API、端口或临时更换Host，不用USB成功冒充AP通过。该结论覆盖以下1.7.1固定地址假设，旧章节为历史。详见[AP验证与缺项](d1-manager-ap-validation-20261109.md)。

## 用户流程与导航

购买/借测客户和售后人员使用：Type-C 自动发现或同网段按 IP 连接 → 读取 D1 健康报告 → 查看设备应用/板端版本、相机、存储、遥测、告警 → 运行只读检测 → 按证据处理后复检 → 预览本次健康观测与摘要 → 保存本地诊断包。用户自行决定分享，不自动上传。上传按钮目前禁用，等待用户提供总服务后端正式接口，不能假设它与OTA或用户中心为同一服务。

父级导航为 **设备管理区 / 数据工作区**；设备管理区下为 **首页 / 设备信息 / 检测排障 / 日志与支持**，数据区沿用校对/检查/导出/批量。数据路径、选择目录/SD卡、错误历史、审核总览/任务中心及数据通知仅随数据工作区显示；软件版本历史、更新和账号为公共入口。已有数据区的路由、权限、离线模式不变；切离时保存草稿/审计、暂停播放及快捷键，失败仍留在当前会话。切回保留已加载数据/帧/草稿。设备区不生成审核活动或计入有效审核时长。多 USB 候选要求选择连接，不任意选一台。

设备模拟入口、场景选择、模拟身份、合成日志和模拟 IPC 均从生产路径移除。测试中的本地伪服务/fixtures 仅验证状态和边界，不作为真实设备测试证据。浏览器页面不连接设备、不生成可运行的假设备数据。

## 模块与操作边界

| 模块 | 契约 |
| --- | --- |
| 前端 `backend.ts` | 统一固定 IPC；传接口 ID、操作 ID，按IP模式另传用户输入的IPv4字面量；不传任意URL/端口/路径/命令/密码 |
| Rust `d1_link.rs` | 只读 OS 连接信息；默认USB限定，按IP模式只枚举活动Ethernet/Wi-Fi网卡并按同网段筛选，网关/IP不等同认证 |
| Rust `d1_device.rs` | 生产 allowlist 只有 `read_health`；重新核对选定接口、USB唯一私有网关或用户指定同网段私有IPv4，绑定本机源地址，固定 `GET /health` / 80；禁代理、重定向、DNS/网段扫描；响应 ≤512 KiB、连接 ≤2秒、请求 ≤5秒 |
| Rust `d1.rs` | 真实结果与运行归属；主动检测共用 TaskControl、支持取消。轮询为单飞有界健康读取，完成后间隔3秒，不后台启动重任务 |
| 诊断包 | 只允许后端实际运行记录，经字段白名单及敏感文本过滤；原子 no-replace；无任意日志路径收集或上传 |
| 未来 OTA | 独立于 Manager 应用更新；未接入时不请求预留服务或设备升级接口，不将源码包当作升级授权 |

健康响应 HTTP 200/503 均须通过 DOHC schema/设备 ID 检查；503 有有效报告表示设备报告异常，不能当纯网络错误。JSON/字段/协议缺失、超时、断连为无法判断/不支持。响应后重新核对选定链路和源/目标地址，连接变化拒绝把结果附到旧连接。鉴权在异步前后检查，结果按账号/会话隔离；切换工作模式清空运行记录。

结果五类：正常、异常、无法判断、不支持、未执行。每项有原观测、接收时间、设备应用版本、规则依据与建议（卡片内按需展开，当前规则`dohc-health-v2`）；不自行编造阈值。相机恢复中不是损坏；heartbeat 过期时不把旧相机/存储状态当新结论。长时 QC 未执行明确显示“未执行”，当前读取不能宣称已启动长时测试。供电告警沿用设备报告。

只读查询自动执行；未来可恢复操作须固定协议/参数并明确确认；重启、长时占用、升级等中断设备的操作须单独设计和二次确认，当前不存在可用写设备入口。

## 本地诊断包

包格式 `d1-manager.diagnostic-package.v2`、`source: physical_device`，默认包含：

- `manifest.json`：应用版本、设备身份/版本、观测范围、收集时间、文件大小/SHA-256，明确 `realLogsCollected:false`、`uploaded:false`。
- `diagnostics.json`：本次实际查询的状态、判断、证据；查询失败也如实保留，无虚构身份。
- `health.json`：仅当范围包含本次有效观测时才有，内容为受限健康字段；不是原始设备日志。

不包含人员名称、任务、账号、审核队列、SSH/连接密钥或任意原始 JSON；设备可变文本含凭据/个人字段标志或控制符时丢弃。原始设备日志尚未采集，不承诺此过滤器覆盖未知日志格式。预览 hash 必须匹配最终包；每文件独占 partial、flush/sync、回读，最终使用 `storage::publish_noreplace`；失败/取消清理自身 partial，已有包不覆盖。

## OTA 与协议待确认

`config/d1-manager.json` 的 `deviceOta` 原样登记 `deltadevice.cn:4174/ota/latest`，scheme null、enabled false、status waiting_interface。不得擅自请求或用 `/ota/v1` 替代。`productionOperations:["read_health"]` 只登记已实现健康只读操作，不启用 OTA。

收到的源码已确认 DOHC 应用 OTA 的签名/摘要、正式 deb 与历史 tar、五文件中继和状态/取消边界。complete 会开始升级，不能当只读上传完成检查。仍需：目标设备的 OTA 部署和 USB 监听/认证契约；预留地址与签名 channel/manifest 的关系、正式 scheme/API；认可的公钥/key ID/轮换与签名样包；兼容型号/revision、供电/存储/空闲门禁与恢复证据。板级固件另做。真实升级另行批准；当前不下载/上传/升级。

DCI 主动检测和原始日志另需正式命令/参数/错误码/输出版本、只读日志范围/格式/轮转/时间基准及真实过滤样例；不把代码仓库里出现某个路径等同开放任意远程收集。
