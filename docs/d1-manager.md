## 用户与主流程

| 用户 | 主要目标 | 当前可用范围 |
| --- | --- | --- |
| 购买/借测客户 | 自查、理解现象、提供必要证据给售后 | 新导航与模拟体验；真实设备未接入 |
| 售后工程师 | 查看身份/版本、复现、按证据排障和复检 | 同上；命令映射等待正式协议 |
| 原数据审核员/管理员 | 原回放、标注、审核、任务、NAS 和管理 | 原工作模式与权限保持 |

未来真实流程：选择并验证设备 → 读取身份/固件/能力 → 运行只读检查 → 查看状态、证据和建议 → 用户处理后复检 → 明确选择时间范围 → 预览文件和隐私说明 → 本地导出 → 用户自行交给支持人员。默认不上传，无远程代操作。

导航：**首页 / 设备管理 / 检测排障 / 日志与支持 / 数据工作区**。新装/离线进入首页；选择/恢复数据目录可直接返回数据工作区。切离数据区必须暂停播放、停用编辑器和全局快捷键、结束当前审核会话；切回保留数据/帧/草稿。管理权限不由导航赋予，所有旧 IPC 门禁保持。模拟区不是审核活动。

完整保留：多路视频/JPEG 与真实时间回放、SMPL/COCO 骨架及独立模型、动作/骨架片段编辑、草稿/修订/特殊标签、通过/不通过及冲突校验、检查/报告/定位、MCAP/HDF5/LeRobot 与批量导出、用户中心/账号/监管、任务领取/云 QC、NAS 待写与恢复、错误历史、版本历史/应用更新。数据工作区路由名称、存储键与格式继续沿用。

## 模块与安全边界

| 层 | 职责 | 当前限制 |
| --- | --- | --- |
| React 外壳 | 导航、状态、证据展示、用户选择 | 只通过 `backend.ts` 调用固定 IPC，不执行 shell/任意命令 |
| Rust 设备域 | 强类型 target、能力、固定操作、任务生命周期 | 生产 allowlist 为空，不接收 host/密码/命令字符串；唯一可运行 target 为本地模拟 |
| 检测规则 | 将观测与版本能力映射成结果 | 模拟规则带 `fixture-v1`，不是 D1 硬件阈值；未知不能通过 |
| 诊断包 | 后端可信运行记录、最少字段、预览/hash/原子发布 | 仅后端生成的模拟摘要和合成日志；无任意文件路径收集和上传 |
| 未来传输/OTA | 认证、主机身份、协议适配 | 等待材料；不导入应用更新器作为设备升级器 |

任务统一使用既有 TaskControl；取消仅针对对应 operation ID，旧取消不得影响新任务。请求结构拒绝未知字段，模拟 ID 明确带 `simulated:` 前缀。模拟能力/固件不得显示为真实连接，页面与诊断包都带模拟标记。切账号/工作模式清理模拟会话。

诊断结果为五种：`normal` 正常；`abnormal` 具有确切规则证据的异常；`indeterminate` 证据不足（包括超时、断连、解析失败）；`unsupported` 版本未支持；`not_run` 尚未执行或取消未运行。每项包含名称、观测证据、观测时间（未运行则为空）、规则版本/适用固件与建议。整个任务另有完成/超时/断连/取消状态，不把传输错误当硬件损坏。复检生成新运行，不改历史运行。

## 风险分级与待确认协议

| 级别 | 示例 | 开放条件 |
| --- | --- | --- |
| 只读 | 身份/版本/状态、日志读取 | 正式命令/字段/权限/超时有证据，固定 allowlist |
| 可恢复 | 经协议确认的配置操作 | 单独设计、参数校验、展示影响、用户确认；当前不提供 |
| 中断设备 | 重启、升级、会停止采集的操作 | 单独验收、明确二次确认和前置条件；当前不提供 |

必须由用户/设备团队提供：真实 `dci help` 和成功/失败样例；命令白名单/参数/错误码/超时；传输/端口/认证/密钥保管；设备发现、序列号、型号、硬件 revision、主机身份与配对/解绑；固件/协议版本和能力 schema；检测项、阈值、单位、有效采样窗口、建议依据；日志目录、格式、轮转、时间基准与允许字段；取消/断连后的任务恢复语义。架构图只表达模块关系，不是协议规范。

收到材料后先做映射和审查，先测本地伪服务/隔离夹具；只在用户提供测试设备并明确授权后执行实机只读查询。真实修复/写设备/OTA 不在当前范围。

## 诊断包契约

真实日志未知，本次只实现后端模拟运行的打包接口。导出目录含 `manifest.json`、`diagnostics.json`、`logs/simulation.jsonl`，清楚标记 `simulated`。范围限定到运行起止时间，预览显示范围、各文件大小/SHA-256、生成时间、来源和过滤数量。manifest 记录应用版本、模拟设备/固件、规则版本、文件摘要；manifest 自身不递归自 hash。

只允许可信结构中的身份/检测字段；合成日志按字段白名单生成，丢弃含密码/token/authorization/bearer/密钥/私钥/个人字段的消息，不在错误中回显其内容。真实收集器引入前必须提供该设备日志格式的独立过滤测试，不能宣称通用文本过滤覆盖所有现实敏感信息。

单文件与总包有界，逐文件独占 partial 写入、flush/sync、回读 hash 和结构核验，取消/错误清理本次 partial；最终使用既有跨平台 atomic no-replace 发布，已存在的正式目录拒绝覆盖。用户预览后导出必须匹配同一 plan hash。禁止自动收集审核队列/账号/路径/源文件，上传功能不存在。

## 品牌与升级兼容

本次可见品牌和主窗口/网页标题变为 D1 Manager。`productName: Delta Viewer` 暂保持，因为 NSIS 注册/升级、Mac `.app` 路径、deb desktop/metadata 与自动验证均依赖它。旧 `Delta-Viewer_*` installer/updater 名称和固定 GitHub 仓库、latest.json target、内嵌公钥均保持，不增加别名或弱化验签。

`com.dohc.viewer`、binary/crate、appLocalData 的 derived root、`user-center.json`、workspace-mode、offline-local、review-outbox、待写结果库、任务与 annotations、草稿/localStorage 键、源 JSON schema 都不迁移或重写。保持 app identifier 是必要条件，三平台覆盖安装的实际数据保全仍需原生 sentinel 验证，不能用代码审查冒充已完成安装验证。

骨架标注的用户数据交付文件为 `skeleton.description.json`。新版把 review-state 内部元数据存放在 `.session_meta/.d1-manager`，并继续读取旧目录内的 review-state 侧车；不会自动删除旧侧车。`.description.lock` 保留在数据目录以维持新版与 1.6.2 的跨版本写互斥，它是锁文件，不是骨架输出；不得自动删除。

将来安装品牌改名需单独设计并测试：Windows 两代注册键/卸载项/安装路径/快捷方式；macOS 应用 bundle 路径与 updater 目标；Linux package/binary/desktop/metainfo；三平台登录配置、队列、草稿和历史哨兵在覆盖升级后逐字节保持。安装品牌和资产改名不得混在当前外壳变更里。
