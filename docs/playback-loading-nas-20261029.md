# 2026-10-29 多账号加载停滞与任务中心超时

调查对象是 Windows 10.1.41.119 的实际交互会话及 NAS 10.1.40.2。用户补充多个账号、更换旧版后均无法加载。所有现场读取只读；没有代审数据、清理 NAS、调整 RAID、断开共享或重启业务服务。

## 结论与证据

本次共同故障已定位至 NAS 存储读取阻塞。共享连接仍然建立，不能简单称为挂载断开或新版独有退化。软件存在可减少的额外读取，但无法绕过操作系统一次文件打开数十秒的阻塞。

目标数据是 `Delta-D1/D1-Daily/2026-09-02-Dish Washer/Dish_Washer_013`，主视频约 61 MB、约 15 秒，状态 530,633 字节、清单 20,854 字节。并非超长视频才会触发。

Windows SSH Session 0 没有交互用户的共享凭据；它报告路径不可访问，不能用来证明数据不存在。以上均来自正确的 Session 1。Windows SMB3.1.1 的 Datasets 连接存在，445 端口可达，读取最终成功，未出现凭据拒绝。

NAS 的 `smbstatus -b` 将目标机映射到 smbd PID 6185；该进程 `/proc/6185/stack` 明确停在 `raid5_get_active_stripe → raid5_make_request → md_submit_bio → btrfs_readpage → pread64`。其他 SMB 进程也处于 D 状态。此为对应客户端请求阻塞在 NAS RAID 读取的直接证据，无需靠软件截图推断。

`/volume8 → cachedev_1(dm-14) → vg5-volume_8(dm-4) → md6`；md6 正在 RAID5 reshape，采样约 11.7%、39 MB/s，10/10 成员在线、degraded=0。不能把重整说成已确认磁盘损坏。系统 IO full 压力约 62–66%，CPU 较低。/volume8 可用与空闲均为 0 字节；不能称为“内存满”，NAS MemAvailable 当时约 5.5 GiB。

NAS 本机及另一 Linux SMB 客户端已缓存的小索引读取可以很快，这不否定 Windows 现场阻塞：请求/文件/缓存命中和时间不同；没有把一次缓存命中当作全部客户端已恢复。

## TASK_INDEX_TIMEOUT 的含义

客户端通过共享目录读取 `Delta-Viewer-TaskIndex/Delta-D1/status.json`、index 及分组节点。前端 20 秒期限到达后保留上次结果，底层未结束的同一请求继续单飞，避免重试不断累积线程。实际两个小文件总读取已超过期限，故提示真实，并非用户中心 HTTP API 登录失败。

NAS index 最近完整统计时间为 `2026-10-27 23:18:51.100 +08:00`。调查中 status 表示 running，但心跳停在 `2026-10-29 13:48:51.666 +08:00`，sessions=0；不能将 running=true 或旧缓存显示为统计已恢复。任务中心旧进度可能落后，应待统计成功后再核对，不能伪造最新时间。

## 1.4.8 客户端改动

- MP4 atom/stts 使用 64 KiB 有界缓冲及缓冲内 seek，跳过 mdat 主负载，保留恒定时钟门禁、变帧率回退及真实采集时间映射。隔离 fixture 相同 30 FPS 结果，底层 read 从 20 次减至 2 次，读取约 65.7 KB，不扫描 2 MiB 媒体负载。此数字仅为元数据解析回归，不代表整条数据加载提升十倍。
- Delta-D1 固定预览根先按路径名称定位，避免每路相机先逐个探测 episode、批次、分组下的不存在预览目录。其他数据布局继续兼容。
- 加载进度展示卷信息、清单/分段、文件元数据、完整状态及指纹复核；八秒无进展显示实际等待和存储排查建议，取消入口保留。操作系统已在途的文件读取不保证能立即中断。
- 检查完成前说明“正在读取视频”，仅画面实际出现后可预览；不再黑屏时宣称“视频可预览”。任务中心超时解释 NAS 响应慢/容量/共享等可能原因，不直接断言挂载掉线。
- 源数据、完整验证/指纹、安全门禁、骨架算法/时间轴、审核结论、队列及任务进度统计语义保持。

## 恢复边界

存储管理员需要检查存储管理器中 volume8 的扩容/重整进度、磁盘健康、其他并发 IO，并安排容量恢复。是否调整重整速度或业务优先级需要结合阵列健康决定；本次没有修改内核参数、终止重整、关闭 SMB 或删除数据。软件重装、重复刷新、回退版本不会解决这类底层等待，也不应清除本机审核队列。

NAS 恢复后，先用同样只读脚本重测小索引和数据文件，再核对任务中心实际服务器统计时间与原待写结论写回。用户确认写回前保留本机结果，不在测试中提交真实审核。
