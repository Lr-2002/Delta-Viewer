# 片段范围偶发混乱：补充排查与修复（1.5.7）

## 结论与证据边界

已证明是软件中两种不同的区间处理问题，不是 NAS 随机改动帧号：1.5.6 修复了保存端错误扩展新片段；本次另复现了 1.5.6 的“连续删除后恢复”在提交前直接制造重叠。并不是每次切分都会触发，不能用一次正常操作排除问题。

NAS 只读核对 Sofa_617：原机标 43 段连续，已有 description.json 保留的 26 段中存在交叠，其技术记录标注写入版本 1.5.4。例如公开左闭右开范围 [987,1127)、[1043,1439)、[1127,1339) 互相覆盖。当前 1.5.6 仍能加载历史异常，并不证明这些范围首次由 1.5.6 写入。截图当前为待审核草稿且混有机标与人工区间；未取得截图主机的本机草稿及操作顺序，无法将该截图精确归因到一次恢复点击。此次没有修改真实人工结果、session/QC、机标或视频，也没有重新审核任何真实数据。

## 可重复触发的新根因

从三段 [0,10)、[10,20)、[20,30) 开始。删除第一段后，后继接续成 [0,20)；再删除这个后继，删除历史中同时存在 [0,10) 与 [0,20)。旧 restoreReviewSegments 仅从当前存活片段扣除恢复范围，却把每个删除历史直接重新显示，输出 [0,10)、[0,20)、[20,30)。前两段重叠，尚未向 NAS 提交就已发生。新增最小回归在修复前失败；固定种子的组合操作回归也在第 50 次操作复现重复帧。

## 修复行为

- 恢复删除历史按起点、终点、稳定索引排序，逐段只分配尚未占用的帧；有多块剩余时保留文字并分为独立身份，完全被覆盖的历史保持删除。交叠删除历史先弹出明确规则与确认，取消不保存。这是生成可核对草稿，不能声称推断出历史真实人工意图。
- 审核主界面对当前有效片段的重叠显示具体帧号和两个定位入口。通过按钮、Enter、保存接口、SQLite 结论入队和 NAS 发布均拦截交叠的通过结论。异常动作仍可查看、编辑并持久保存待审核草稿；不通过继续仅保存结论，不发布尚未批准的动作编辑。删除历史本身允许交叠，不作为有效片段校验。
- 旧待写通过结论若已经交叠，补写失败时保留原事件 ID、时间和片段，不删除、重试改写或伪称成功。用户需重新编辑核对后再审核。
- 应急草稿来源指纹变化时先备份，保持当前加载来源；交叠应急结论仅按待审核恢复，防止直接再提交。不能仅因范围单独合法就把草稿当成合法完整切分。
- 相邻段共享显示边界合法：界面与人工 JSON 为 [start,end)，上一段 end 等于下一段 start；内部闭区间则上一段 end + 1 等于下一段 start。此次不强行填满合法空白，也不按比例移动/缩放历史片段。
