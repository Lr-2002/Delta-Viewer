# 机标与视频帧数不一致调查及修复（1.2.4）

## 结论

截图中的 Sofa_050 可以精确匹配机标 episode_id；失败是片段超出当前视频范围，不是目录编号失配。采集清单和 MP4 帧表均为 1211 帧，机标声明 1429 帧，共 25 段，其中一段跨越视频末帧、三段完全越界。此前 Washing_576 同类问题为实际 373 帧、机标 389 帧，一段跨尾、一段完全越界。

纯目录移动/重命名不会改变 MP4 帧数。若整理中换了视频、截断视频或混入另一版机标，也可能造成这种现象，但当前没有历史媒体/生产记录可以证明是哪一环节。Sofa_050 的生产端文件元数据指纹与当前值不同；该指纹包含修改时间，移动或复制也可能改变它，不能据此断言视频内容被替换。机标文件还包含另一个 Sofa_050-2 结果，不得随意改选它来消除错误。

对齐阻断在 1.0.2 已存在。1.1.3 仅在所有片段本就在当前视频范围内时适配总帧数；真实越界仍保留警告。近期任务中心及骨架描述修改不是该检查的引入点，未发现它们修改源视频或机标的证据。

## 修复

- 保留原始帧数、所有原始文字和边界，新增“查看越界片段并处理”，列出受影响片段和处理数量。
- 核对视频并明确确认后只取范围交集：跨尾片段截去越界尾部，完全越界片段保存为 deleted 技术历史，不出现在有效人工 annotations。不缩放、不新增虚构帧。
- 保存前将原机标和已有人工结果原字节持久备份到本机。备份失败中止覆盖。原机标、媒体及其他 episode 不改动。
- 处理保存为 pending，已有通过/不通过撤为待审核。需回放核对全部保留片段并勾选后方可通过；再编辑撤销勾选，也可正常判不通过。
- 重新打开、重启和新主机读取保留已处理范围和技术历史。恢复删除不可恢复越界段。后端仅容许精确原机标范围的 deleted 历史；所有有效片段必须在 Camera 0 范围内。
- 视频清单与已加载工作区不一致时要求重新加载，避免按过期帧数处理。人工结果审核信息继续只保留状态、审核人、日期，技术信息独立保存。

## 验证与限制

隔离测试覆盖 0/1 基帧号、闭/半开区间、跨尾和完全越界、非法恢复、原字节备份、备份失败、其他 episode 保留、人工结果精简、通过/不通过、同机和新主机重开。浏览器覆盖取消不写入、明确确认、回放核对门禁、编辑撤销确认、保存失败重启恢复，以及 1440×920、960×680、390×844 提示及按钮可见。

真实 NAS 仅做只读核查，不用真实审核数据测试保存；未修改历史结论、机标或媒体，未重启工作台/用户中心。范围交集不能证明动作与当前画面正确对应，也不能恢复缺失画面；仍需审核员回放判断。安装与目标机验证结果另保存在交付测试报告，不以浏览器模拟代替 Windows 原生验收。
