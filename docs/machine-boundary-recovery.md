# 机标缺失结束帧与原因排序（1.0.62）

当机器生成的 annotations 某项 end_frame 为 null 时，旧版 u64 反序列化会拒绝整个文件，因而显示零片段；对应 segments 也可能缺少该字段。JSON 文件存在并不代表内部字段完整。

新版只对机器来源的中间片段作有提示的临时推定：所有起点须严格递增，下一片段存在，推定范围须通过原有帧数及起点校验。半开区间取下一片段起点，闭区间取其前一帧。不是模型原始边界的确认，不保证动作在该帧结束；审核员须回放、调整并确认后才可通过。末段缺界、起点 null、非法类型、倒序和越界仍报错；已保存人工结果不会自动推定。

源 JSON 字节和哈希保持不变。只有正常人工保存才更新人工结果 description.json 中的 annotations 与关联 segments；不会修改百炼输出。正常 QC 保存及审计补传流程保持原规则。

拒绝原因新增“动作失范”。点击“调整顺序”可拖动标签或使用 Alt + 方向键移动；完成后恢复单击选择。顺序保存在当前本机、当前账号，恢复默认不改 QC。其他原因固定右下角。存储失败明确提示，不能声称排序已经保存。

回归覆盖空结束帧、区间和索引基数、非法和歧义范围、原机标字节不变、人工双数组回写与新本机重载、新原因保存与重载、排序不误选、账号隔离和窄屏布局。私有真实样例与截图仅保存在本机 artifacts，不进入发布仓库。
