# 机标可选属性兼容读取（1.1.4）

旧解析器要求每个 `T`/`value` 属性项目都完整，一个非必需属性缺少 `value` 就返回 `MACHINE_ANNOTATION_INVALID: 机标属性缺少 value`，导致整份机标的片段和描述不可见。该问题与目录编号核验是不同的解析路径，1.1.3 未覆盖。

## 原因与读取规则

实际问题样本中，某个非描述属性写成了 `{"T":"interaction_method","unexpected_key":"..."}` 一类结构，中文动作描述、片段边界及其余属性仍完整。新解析器不推测未知键是否代表值：该属性的读取视图保持空值，其他可用字段继续加载。原始内容完整保留在 `source_json` 中。

- 支持原对象属性和 `T`/`value` 数组；空属性继续可用。
- 没有名称或不是属性对象的条目留在原始 JSON 中，不进入用于显示的属性映射，并记录兼容提示。
- 重复相同值可以读取；空值与唯一非空值共存时使用非空值。存在多个不同的非空值时不选择其中任何一个，并提示冲突。
- 描述不是文本时不转换为虚构文字，保留其他可用语言的描述或显示空白供人工补充。
- 片段边界、文件上限、账户门禁和保存冲突规则不变。

## 提示与保存

动作片段区显示“部分机标属性格式异常，已兼容加载，请核对动作描述”，展开后列出源片段序号、语言和原因；仅列出前 50 组异常并说明总数，避免大文件提示挤占审核区域。正常文件不显示此提示。

加载保持只读。正常人工编辑时只更新目标描述，不清洗或改写不相关属性。目标描述重复时更新该字段的所有副本，避免保存后又读取冲突；目标属性本身为历史标量时，将原内容保留在数组中，再追加人工描述项目。原机标文件始终不修改。

## 验证范围

隔离回归覆盖：非描述属性缺少值、空/无名条目、重复相同值和冲突值、非文本描述、异常属性容器、人工修改后通过/重开、源机标字节不变，以及 1440、960、390 像素宽度的提示和编辑可用性。实际问题机标在隔离目录读取，不在 NAS 上保存或修改审核结论。
