# 动作片段审核通过后发布（1.3.1）

2026-10-26，基于 1.3.0（11d8fff）。

## 原因

旧版 MachineAnnotationPanel.change 调用 persist(pending)，save_machine_review 最终调用 save_for_user_mode；该函数在 pending 状态也生成 published 结果并更新 description.json / desorption.json、技术侧车及 session.json。因而原行为不满足“通过前不体现动作修改”的新要求，不能仅保留旧逻辑。

## 本次行为

- 所有动作编辑继续自动保存，但改存本机 SQLite FULL/WAL，按用户中心、账号、目录和来源隔离。保存不探测 NAS，不修改共享结果、QC 或技术侧车。重开后恢复草稿。
- 审核通过先在同一事务保存结论和原 ID/时间的操作回执，再尝试发布当前片段。NAS 满/不可用时返回本机待写状态，不伪报共享完成；恢复后确认补写。
- 不通过提交原因、审核人、日期与结论；人工 JSON 的片段取共享内容或原机标，绝不使用未批准的编辑快照。共享已有人工文件时只更新审核元数据，保留 annotations 原内容。本机替换前的草稿历史仍保留。
- 通用待写回入口排除新旧 pending 动作条目，不能绕过审核。侧栏及编辑器明确显示本机草稿，不宣称正式结果已保存。纯草稿不阻止批量不通过，实际未确认结论继续阻止重复提交。
- 反向拖动复原、越界确认、增删、切割和恢复共用草稿路径。骨架描述没有审核流程，保持独立自动保存。
- 原共享哈希、修订、来源及 QC 基线继续用于并发防覆盖。共享内容变化时保留本机结果并报冲突；未确认条目不删除。同一未确认结论再次点击重试沿用原 ID/时间。

## 验证

- pnpm check:full：通过。Rust 231 通过，15 环境/私有数据测试跳过；Clippy、格式、前端构建、Tauri debug no-bundle 构建通过。
- 新增原生隔离回归：草稿期间共享全部普通文件字节不变、文本/增删/边界通过后准确发布、再次编辑已通过结果、重开恢复、账号/服务隔离、通用写回拒绝草稿、不通过不发布修改、本机磁盘失败、NAS 满与幂等补写、共享 QC 冲突保留队列。
- 发布脚本、Wiki 链接、审计持久性及源结果补写浏览器测试、并发工作流 smoke 通过。完整校对/回放浏览器回归和三平台 Release 由同一发布提交的 CI 再执行；目标 Windows 实际 JSON 验证证据保留在 ignored artifacts/action-approval-1.3.1。
- 不更新或重启用户中心、工作台或上传服务，不修改实际 NAS 原始数据或已有历史结论。没有恢复或推测历史缺失事件。

## 范围与限制

草稿保存在当前电脑；切换电脑无法自动读取另一台电脑的未提交片段。只有通过后的结果（或显式提交的待写结论）进入共享发布流程。共享任务进度继续取实际 NAS QC，用户中心的本机完成回执不表示 NAS 已写或工作台已统计。

## 1.3.2 交付补充

发布前复查发现，沿用旧 NAS 故障队列互斥会误拦不同来源的普通草稿。1.3.2 将互斥收窄为已提交待写回结论；各来源草稿独立保留，共享基线变化仍拒绝覆盖。增加双来源草稿原生回归，并重新执行完整门禁。最终桌面交付及目标 Windows 测试使用 1.3.2。
