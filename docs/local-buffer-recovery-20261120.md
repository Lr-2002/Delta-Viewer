# 七路共同恢复等待修正

日期：2026-11-20；候选：1.13.0。

## 实机故障

用户在1.12.9登录后实际打开本地任务30.5秒七路，主相机4K，全部D3D11硬解。首轮3×实测约7.94秒仅推进2.34秒，次轮约13.97秒推进20.15秒，均不合格。主路曾在readyState3时暂停，多次等到0.75媒体秒额外储备；其他六路已就绪。readiness恢复不等于网络、GPU都能稳定满足3×。

首轮只读诊断脚本原有status=passed表示采样完成，与速度并无断言，不能作为验收。后续已改measured，保留原数据与全部不合格结果。一次主路只读16MiB读取耗时1.52秒，只能说明该次读取速度，不能代替七路长时间吞吐测量。

## 修正

保留HAVE_FUTURE_DATA门槛；没有后续帧时健康镜头仍共同等待，饥饿镜头保持解码意图并暂以min(所选速率,2)恢复。浏览器已将网络状态设为NETWORK_IDLE时，不再要求暂停解码器取得额外压缩储备；仍在加载时额外补充最多250ms。只有可播放的未来帧已存在时才适用此上限，不是超时忽略缺失视频。整组恢复前立即还原用户倍速。

共同等待期间停止副路调速纠偏，防止它把恢复速率改回高倍速。原始画质、七路、帧时钟和主动定位保持，不增加连续定位，不改源文件或审核。
